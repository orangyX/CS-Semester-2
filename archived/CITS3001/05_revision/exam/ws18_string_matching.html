Part A · Rabin–Karp

3 questions · ~40 min

Slides 9–12. The one idea to hold onto: a hash mismatch proves the window is wrong, a hash match proves nothing. A2 is the highest-value item, because the rolling update with a negative intermediate is exactly where hand-traces go wrong in an exam.

A1trace

Text over the alphabet $\{a, b, c\}$. Give each letter a value, $a = 0$, $b = 1$, $c = 2$. With three letters the base is $d = 3$, so a 4-letter window is a base-3 number: for example bbcb $= 1\cdot 27 + 1\cdot 9 + 2\cdot 3 + 1 = 43$. Use $q = 11$.

T = bbcbccbabcabba    P = ccba

The pattern has $m = 4$ letters and the text has $n = 14$, so there are $n - m + 1 = 11$ windows: the 4-letter blocks $T[s..s+3]$ for $s = 0$ to $10$. The first is bbcb, the next bcbc, and so on.

  1. Convert $P$ to its base-3 value and compute $p' = (\text{value of } P) \bmod 11$. This is the number every window gets compared against.
  2. For every window, compute $z' = (\text{value of window}) \bmod 11$. Do the first one directly, then use the rolling update for the rest (A2 practises the update in detail).
  3. Compare each $z'$ with $p'$ and mark the window: skip if $z' \ne p'$; if $z' = p'$, compare the window with $P$ letter by letter and mark it valid or spurious. How many windows needed that letter-by-letter check?

Precompute $h = 3^{3} \bmod 11$ once; every update then needs only small numbers. No window is worth more than cccc $= 80$, so checking any $z'$ directly is quick.

Set-up

ccba $= 2\cdot 27 + 2\cdot 9 + 1\cdot 3 + 0 = 75$, so $p' = 75 \bmod 11 = 9$ (since $11 \times 6 = 66$). The leading-letter weight is $h = 3^3 \bmod 11 = 27 \bmod 11 = 5$. First window: $43 \bmod 11 = 10$.

The slide 12 code does exactly this with ord(c) as the letter value and $d = 256$; the steps are identical, the numbers are just bigger.

A2trace

Same $T$, $P$, $q$ as A1. Starting only from $z'_0 = 10$ and $h = 3^3 \bmod 11 = 5$, use the update formula (no recomputing from scratch) to get $z'_1$, $z'_2$, $z'_3$. Show every intermediate value, and say what goes wrong at $z'_3$ if this were written in C or Java with %.

Formula

$z'_{s+1} = \big((z'_s - v(T[s])\cdot h)\cdot 3 + v(T[s+4])\big) \bmod 11$, where $v$ is the letter's value.

$s = 0 \to 1$

Drop $T[0] = b$ (1), add $T[4] = c$ (2): $(10 - 1\cdot 5)\cdot 3 + 2 = 17$, and $17 \bmod 11 = 6$.

$s = 1 \to 2$

Drop $T[1] = b$ (1), add $T[5] = c$ (2): $(6 - 1\cdot 5)\cdot 3 + 2 = 5$, so $z'_2 = 5$.

$s = 2 \to 3$

Drop $T[2] = c$ (2), add $T[6] = b$ (1): $(5 - 2\cdot 5)\cdot 3 + 1 = -14$. The mathematical residue is $-14 + 2\cdot 11 = 8$, so $z'_3 = 8$.

Checks

All three agree with the A1 table (6, 5, 8) ✓, and directly bccb $= 27 + 18 + 6 + 1 = 52 = 4\times 11 + 8$ ✓.

The language trap

Python's % always returns a value in $[0, q)$, so -14 % 11 is 8 and the slide code is correct as written. In C or Java, -14 % 11 is -3; comparing $-3$ with $p'$ would silently miss matches. The fix there is ((x % q) + q) % q.

How to use this: on paper, whenever the subtraction goes negative, add multiples of $q$ until it is back in range before continuing.

A letter's value is ord(c) - ord('a'). Reduce mod $q$ after every update so the hash never grows past one machine word.

Approach

The slide 12 code with the given $d$ and letter values ord(c) - 97 in place of ord(c), counting the two outcomes of each check instead of collecting shifts. One pass, $O(n + m\cdot\text{hits})$.

Reference solution 
import sys

def main():
    data = sys.stdin.read().split()
    d, q = int(data[0]), int(data[1])
    text, pattern = data[2], data[3]
    n, m = len(text), len(pattern)
    if m > n:
        print(0, 0)
        return
    high = pow(d, m - 1, q)
    p = z = 0
    for j in range(m):
        p = (d * p + ord(pattern[j]) - 97) % q
        z = (d * z + ord(text[j]) - 97) % q
    valid = spurious = 0
    for s in range(n - m + 1):
        if p == z:
            if text[s:s + m] == pattern:
                valid += 1
            else:
                spurious += 1
        if s < n - m:
            z = (d * (z - (ord(text[s]) - 97) * high) + ord(text[s + m]) - 97) % q
    print(valid, spurious)

main()
Checks

Sample 1 is A1 (one valid, one spurious) ✓. Sample 2: abra occurs at shifts 0 and 7, and two other windows collide with it mod 13. Tested against a brute-force residue count on 300 random cases; a $10^6$-letter text runs well inside the limit.

Part B · The matching automaton

4 questions · ~40 min

Slides 13–14. The one idea to hold onto: state $k$ means "the longest prefix of $P$ that ends right here has length $k$." Every transition is computed from that sentence. B4 is the highest-value item: it is the "careful implementation" the slide mentions without showing, and it is KMP in disguise.

Reasoning for the non-obvious entries

$\delta(1,b)$: ab ends in neither a nor aa, so 0. $\delta(2,a)$: aaa ends in aa, so stay at 2; this self-loop is what lets the machine find aab inside aaab. $\delta(3,a)$: aaba ends in a, so 1, as slide 13 says. $\delta(3,b)$: aabb, nothing, so 0. Every $c$ goes to 0 because $c$ never appears in $P$.

Slide 13's diagram draws only $a$ and $b$ arrows, but the running example text contains c. The machine needs the third column, all zeros, to run on that text.

B4reason

Let $\pi(k)$ be the length of the longest proper border of $P[0..k-1]$ (proper prefix that is also a suffix).

  1. Argue that for $k \lt m$ and $a \ne P[k]$, $\;\delta(k, a) = \delta(\pi(k), a)$; and that $\delta(m, a) = \delta(\pi(m), a)$ for every $a$.
  2. Check the rule on three failure entries of B3: $\delta(5,b)$, $\delta(5,a)$, $\delta(7,b)$.
  3. Explain why this gives the whole table in $O(m\,|\Sigma|)$ time, as slide 14 claims.

Any prefix of $P$ that is a suffix of $P[0..k-1]\,a$ and has length at most $k$ must, after dropping $a$, be a border of $P[0..k-1]$ — and every border of $P[0..k-1]$ is a suffix of $P[0..\pi(k)-1]$.

(a)

In state $k$ the relevant suffix is $P[0..k-1]$. Reading $a \ne P[k]$ cannot reach $k+1$, so the answer is some $j \le k$ where $P[0..j-1]$ is a suffix of $P[0..k-1]a$. If $j \ge 1$, then $P[0..j-2]$ is a suffix of $P[0..k-1]$ of length $\lt k$, so it is a border and therefore a suffix of $P[0..\pi(k)-1]$, the longest border. So the candidates are exactly the same whether we start from $P[0..k-1]$ or from $P[0..\pi(k)-1]$: both strings give the same answer after appending $a$, which is the statement $\delta(k,a) = \delta(\pi(k),a)$. This step is exactly where $a \ne P[k]$ is used: without it, $k+1$ would be a candidate that $\pi(k)$ cannot see. State $m$ has no "match" move at all, so the same argument applies to every $a$.

(b)

$\pi(5)$ for ababa is 3 (aba); $\pi(7)$ for ababaca is 1.

$\delta(5,b) = \delta(3,b) = 4$ ✓.   $\delta(5,a) = \delta(3,a) = 1$ ✓.   $\delta(7,b) = \delta(1,b) = 2$ ✓.

(c)

Since $\pi(k) \lt k$, row $\pi(k)$ is already built when row $k$ is reached, so each entry is either "$k+1$" or one table lookup: $O(1)$ per entry, $(m+1)|\Sigma|$ entries. The state $x = \pi(k)$ itself is maintained by running the half-built machine over $P[1..]$, one step per row.

Why this matters: KMP is this same rule applied lazily — instead of storing $\delta(\pi(k), a)$ for all $a$, it follows the $\pi$ link at match time, for only the symbol that actually arrived.

C3reason

Slide 18 says KMP's nested loops still run in $O(n+m)$ time because "the inner loop only ever undoes progress the outer loop has already made."

  1. Turn that sentence into an argument that the matching phase does at most $n$ iterations of the while loop in total, by tracking the value of $q$.
  2. Confirm the bound against C2.
  3. Why doesn't the same argument show that each individual text character is compared $O(1)$ times?

Ask: how much can $q$ increase per outer iteration, how much does each inner iteration decrease it, and can it ever go below zero?

(a)

Track $q$. It starts at 0 and is never negative. Each outer iteration increases $q$ by at most 1 (the single q += 1). Each while iteration sets $q$ to pi[q-1] $\lt q$, so it decreases $q$ by at least 1; the post-match reset decreases it too. Total decrease cannot exceed total increase, which is at most $n$. So there are at most $n$ inner iterations over the whole run, and $O(n)$ total work. The same argument with $k$ bounds prefix_function by $O(m)$.

(b)

C2: $n = 15$; $q$ increases on 14 iterations (every character except the $c$), and the inner loop runs twice in total ✓.

(c)

The bound is on the total, not per character. In C2 the character $T[6] = c$ was compared three times (at $q = 4$, $2$, $0$). One character can be compared up to $O(m)$ times; it is the earlier cheap characters that paid for it. This is an amortised argument.

The moral: "nested loops" is not the same as "quadratic". Ask what quantity the inner loop consumes and who produced it.

The matching loop then has the same shape with $i$ reading the text and $q$ counting matched characters; the only new line is what to do when $q$ reaches $m$. Approach

Two phases. Preprocess: prefix_function(P), $O(m)$. Match: one pass over $T$. For each $i$, drop $q$ with q = pi[q - 1] while $q \gt 0$ and $P[q] \ne T[i]$; then, if $P[q] = T[i]$, increase $q$. When $q = m$, record the shift $i - m + 1$ and reset q = pi[q - 1] so the next, possibly overlapping, occurrence can reuse what was just matched. $i$ never moves backwards, so the whole run is $O(n + m)$ (C3).

Reference solution 
import sys

def prefix_function(p):
    m = len(p)
    pi = [0] * m
    k = 0
    for q in range(1, m):
        while k > 0 and p[k] != p[q]:
            k = pi[k - 1]
        if p[k] == p[q]:
            k += 1
        pi[q] = k
    return pi

def kmp(text, pattern):
    m = len(pattern)
    pi = prefix_function(pattern)
    shifts = []
    q = 0
    for i in range(len(text)):
        while q > 0 and pattern[q] != text[i]:
            q = pi[q - 1]
        if pattern[q] == text[i]:
            q += 1
        if q == m:
            shifts.append(i - m + 1)
            q = pi[q - 1]
    return shifts

data = sys.stdin.read().split()
text, pattern = data[0], data[1]
shifts = kmp(text, pattern)
print(len(shifts))
if shifts:
    print(" ".join(map(str, shifts)))

Part D · Boyer–Moore

4 questions · ~45 min

Slides 19–25. The one idea to hold onto: compare right-to-left, and on a mismatch ask each heuristic "what is the smallest shift that could possibly still work?", then take the larger answer. D3 is the highest-value item: a full Boyer–Moore trace where the two heuristics take turns winning.

$c$imblanceother

$a$ occurs at 3 and 5; the table keeps the rightmost, 5. Every other character (including space) gets $-1$.

(b)

The window is $T[5..13]$ = we notice. $j=8$: $e = e$; $j=7$: $c = c$; $j=6$: $P[6] = n$ against $T[11] = i$, mismatch. Bad character $i$, good suffix ce.

(c)

Bad character: $j - \lambda(i) = 6 - 0 = 6$, lining up the $i$ in $T$ with the $i$ at the front of $P$. Good suffix: ce appears nowhere else in $P$, and no prefix of $P$ (starting with $i$) is a suffix of ce, so no partial overlap can survive either: shift the whole length, 9. Boyer–Moore takes $\max(6, 9) = 9$.

The moral: the slide shows the bad-character move, but at this alignment the good-suffix rule is the one that wins.

(a)

Window $T[5..10]$ = ate ed. $j=5$: $d=d$; $j=4$: $e=e$; $j=3$: $P[3] = t$ against a space. Bad character: space $\notin P$, so $3 - (-1) = 4$. Good suffix ed recurs at the front of $P$, a shift of 4: gs[4] = 4. Both give 4 ✓.

(b)

gs[6] is used when $j = 5$, i.e. nothing matched: no information, so shift 1 (the bad-character rule supplies anything bigger). gs[0] is used after a full match: shift to the next place $P$ could overlap itself, which is the length minus the longest border, $6 - 2 = 4$ (border ed).

(c)

At $j = 4$ the text character under $P[4] = e$ is known not to be $e$. Shifting by 4 would place $P[0] = e$ on that very character, so it is guaranteed to fail. The code's rule only accepts a recurrence of the good suffix whose preceding character differs from $P[j]$; there is none, and the longest prefix of $P$ that is a suffix of d is empty, so it shifts the full 6.

Slide 22's sentence describes the weaker rule ("matches all the characters it still overlaps"), which would give 4 here. The slide 24 code implements the stronger rule, which also uses the mismatched character. The two agree whenever the recurrence is preceded by a different character or by nothing at all, as in (a).

A simplified Boyer–Moore uses the bad-character rule alone, made safe with a floor of 1. Compare right-to-left; on a mismatch at index $j$ with text character $c$, shift by $\max\big(1, j - \lambda(c)\big)$ where $\lambda(c)$ is the rightmost index of $c$ in $P$ or $-1$; after a full match, shift by 1. Report how many occurrences it finds and how many alignments it tries.

Reference solution 
import sys

def main():
    text = sys.stdin.readline().rstrip("\n")
    pattern = sys.stdin.readline().rstrip("\n")
    n, m = len(text), len(pattern)
    last = {}
    for i, c in enumerate(pattern):
        last[c] = i
    s = 0
    found = 0
    tried = 0
    while s <= n - m:
        tried += 1
        j = m - 1
        while j >= 0 and pattern[j] == text[s + j]:
            j -= 1
        if j < 0:
            found += 1
            s += 1
        else:
            s += max(1, j - last.get(text[s + j], -1))
    print(found)
    print(tried)

main()

E1reason

Pick Rabin–Karp, the automaton, KMP or Boyer–Moore for each situation, with a one-line reason.

  1. Find a 20-base primer in a 3-billion-base genome ($\Sigma = \{A, C, G, T\}$).
  2. A text editor's "find" for an English word in a long document.
  3. Scan a network byte stream for an attack signature. The stream can't be re-read, and an attacker controls its contents.
  4. Check every 50-character window of 10,000 submissions against a list of 500 different 50-character fingerprints.
  5. Search for $a^{1000}$ in a text that is almost entirely $a$'s.
  6. Repeatedly search Unicode text ($|\Sigma| \approx 150{,}000$) for a 1000-character pattern.
(a) Automaton or KMP

With $|\Sigma| = 4$ the automaton's table is only $21 \times 4$, and matching is one lookup per base. Boyer–Moore skips little on a 4-letter alphabet, since almost every text character occurs in the pattern.

(b) Boyer–Moore

Large alphabet, ordinary text, most text characters rare in the pattern: long skips, sublinear in practice.

(c) KMP

Worst-case $O(n)$ that an adversary can't break, and the text pointer only moves forward, one character at a time. Boyer–Moore's $O(nm)$ worst case is exactly what a hostile input would target.

(d) Rabin–Karp

Hash each window once and look the residue up in a set of the 500 fingerprint hashes; verify only on a hit. The other algorithms handle one pattern at a time.

(e) KMP

Matches everywhere: Boyer–Moore does $m$ comparisons at each of the $n-m+1$ alignments, and Rabin–Karp verifies every window in full. KMP's reset to pi[m-1] $= m-1$ makes each further match $O(1)$.

(f) KMP (or Boyer–Moore)

The automaton's table would be $1001 \times 150{,}000 \approx 1.5\times 10^8$ entries. KMP's preprocessing is $O(m)$ regardless of alphabet; Boyer–Moore is also attractive here with $\lambda$ stored as a dictionary.

The discriminating questions: do I need a worst-case guarantee, how large is the alphabet, and how many patterns are there?

E2reason

Each claim is false. For each, name the mistake and give a concrete counterexample from this sheet.

  1. "If the pattern's hash equals the window's hash, $P$ occurs at that shift."
  2. "Rabin–Karp runs in $O(n + m)$ time."
  3. "KMP never examines the same text character twice."
  4. "The automaton matches in $O(n)$, like KMP, so it is never the worse choice."
  5. "The bad-character rule is a correct matcher on its own; the good-suffix rule just makes it faster."
  6. "Boyer–Moore is always at least as fast as KMP, because it can skip characters."
(a) hash equality is necessary, not sufficient

A1: window cbab (value 64) has residue 9 mod 11, the same as ccba (value 75), but is not the pattern. Equal residues only license verification.

(b) expected, not worst case

$O(n+m)$ is the expected bound with a good $q$ and few matches. $T = a^n$, $P = a^m$ verifies every window: $m(n-m+1)$.

(c) amortised, not per character

C2: $T[6] = c$ is compared three times. The true statement is that the total number of comparisons is at most about $2n$ (C3).

(d) ignores preprocessing

Matching is $O(n)$, but building the table is $O(m|\Sigma|)$. E1(f): about $1.5\times 10^8$ entries before reading a single text character.

(e) the shift can be non-positive

drab on brabham: at $s = 0$ the mismatch is at $j = 0$ on $b$, and $\lambda(b) = 3$ gives $0 - 3 = -3$. Used alone without a $\max(1, \cdot)$ guard, the matcher moves backwards or loops forever.

(f) best case is not worst case

$a^{10}$ against $a^3$ costs Boyer–Moore 24 comparisons; KMP does it with one comparison per text character. On repetitive input, the skips vanish.

E3reason

Closed book. Write out each from memory, then check.

  1. The pattern-matching problem and the definition of a valid shift.
  2. Rabin–Karp's rolling update, why it works mod $q$, and what a spurious hit is.
  3. The automaton's state invariant and the rule $\delta(k,a) = \delta(\pi(k),a)$ with its condition.
  4. The definition of pi, its two easy properties, and KMP's update after a mismatch and after a full match.
  5. The bad-character shift, the good-suffix idea, and how Boyer–Moore combines them.
  6. The preprocessing and matching costs of all four algorithms.
(a)

Given text $T$ (length $n$) and pattern $P$ (length $m$) over $\Sigma$, find the shifts $s$ with $T[s+j] = P[j]$ for all $0 \le j \lt m$ (slide 4).

(b)

$z' = \big((z - T[s]\, d^{m-1})\, d + T[s+m]\big) \bmod q$. Mod $q$ keeps values in a word; equality mod $q$ is implied by string equality, so different residues reject safely. Spurious hit: equal residues, different strings.

(c)

State $k$: $P[0..k-1]$ is the longest prefix of $P$ that is a suffix of the text read. For $a \ne P[k]$ (or $k = m$), $\delta(k,a) = \delta(\pi(k),a)$.

(d)

pi[i] = length of the longest proper prefix of $P[0..i]$ that is also its suffix. pi[0] = 0; pi[i] ≤ pi[i-1] + 1. Mismatch: q = pi[q-1] repeatedly while $q \gt 0$; full match: report $i - m + 1$, then q = pi[m-1].

(e)

Bad character: $j - \lambda(T[s+j])$, with $\lambda$ the rightmost index in $P$ or $-1$; may be $\le 0$. Good suffix: smallest shift that realigns the already-matched suffix $P[j+1..]$ with another copy of itself in $P$ (or with a prefix of $P$ that overlaps it), from table gs[j+1], always $\ge 1$. Shift by the maximum; after a full match shift gs[0].
