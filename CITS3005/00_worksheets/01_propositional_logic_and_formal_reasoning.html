Lecture 2 — propositional logic and formal reasoning

CITS3005 Knowledge Representation · syntax, semantics, natural deduction, Prolog

This lecture's notation is not CITS2211's. Three differences to fix before you start:

  1. Compact rule labels — (∧El), (→E), (¬I) — not "forall elimination" spelled out.
  2. Assumptions carry a numeric label in square brackets: [α]1. The label reappears on the rule that discharges it: (→I)1(3–5).

01

Syntax and well-formed formulae

~15 min
L = α ::= ⊤ | ⊥ | x | ¬α | α ∧ α | α ∨ α | α → α | α ↔ α    where x ∈ P

1.1 Which are well-formed formulae of L? For any that are not, say which production fails.

  1. ¬ ∧ x
  2. x → ¬y ∧ z
  3. (x ∨) ∧ y
  4. ¬¬¬⊤
  5. x ↔ (y → (z ∨ ⊥))
▶Check
  • (a) No. ∧ is binary and needs two α operands; ¬ has nothing to negate.
  • (b) Yes.
  • (c) No. α ∨ α requires a second operand.
  • (d) Yes — ¬α applies repeatedly, and ⊤ is a production.
  • (e) Yes.

1.2 Draw the parse tree imposed by the BNF.

  1. ¬(x → (y ∧ ¬z))
  2. (x ∨ y) ↔ ¬(z ∧ x)
▶Check

(a) Root ¬, one child →, whose children are x and ∧. That ∧ has children y and ¬, and that ¬ has child z.

(b) Root ↔; left child ∨ over x, y; right child ¬ over ∧, which has children z, x.

1.3 The lecture says BNF makes brackets unnecessary in the formal syntax, yet we still write them. Explain the distinction, and give a formula whose string is ambiguous but whose tree is not.

▶Check

The BNF generates trees. Brackets are an artefact of writing a tree as a linear string — they recover the structure the string loses.

x ∧ y ∨ z is ambiguous as a string, since two distinct trees flatten to it. Each tree is itself a perfectly unambiguous object.

1.4 The lecture separates a logic into syntax and semantics, and separately says a logic requires propositions and consequence. Match the pairs up. Which of syntax/semantics does "consequence" belong to, and why is the answer not clean?

▶Check

Propositions map to syntax. Consequence maps to semantics — but only loosely, and that is the point.

Consequence has two distinct formalisations: semantic entailment ⊨, defined over interpretations, and syntactic derivability ⊢, defined by inference rules with no reference to meaning at all. Section 7 is about when the two agree.

02

Interpretations and formal semantics

~25 min
An interpretation is a map I : P → {T, F}, equivalently the set I ⊆ P where I = {p ∈ P | I(p) = T}.

2.1 Let P = {x, y, z} and I(x) = T, I(y) = F, I(z) = T. Write I in set form. Then convert I = {y} back into function form.

▶Check

I = {x, z}. And I = {y} means I(x) = F, I(y) = T, I(z) = F.

Check this against the recording. Slide 13 sets I(x)=T, I(y)=F, I(z)=F and then states I = {x, y}. By that slide's own definition it should be {x} — y is assigned F, so it doesn't belong in the set. Either the assignment or the set is a typo.

2.2 Let P = {x,y,z} and I = {x, z}. Using the recursive definition of ⊨ — not a truth table — determine whether I ⊨ α. Show the unfolding.

  1. x ∧ ¬y
  2. x → y
  3. ¬(y ∨ ¬z)
  4. x ↔ z
  5. (x → y) → (y → x)
▶Check

Throughout, I ⊨ p ⇔ p ∈ I, with I = {x,z}.

  • (a) Yes. I ⊨ x ∧ ¬y ⇔ I ⊨ x and I ⊨ ¬y ⇔ x ∈ I and I ⊭ y. Both hold.
  • (b) No. I ⊨ x → y ⇔ I ⊨ y or I ⊭ x. But y ∉ I and x ∈ I, so both disjuncts fail.
  • (c) Yes. y ∉ I, and I ⊨ ¬z ⇔ I ⊭ z fails since z ∈ I. So I ⊭ y ∨ ¬z, hence I ⊨ ¬(y ∨ ¬z).
  • (d) Yes. Both x → z and z → x hold since x, z ∈ I.
  • (e) Yes, vacuously — the antecedent x → y fails by (b).

2.3 The semantic clause for implication is I ⊨ α → β ⇔ I ⊨ β or I ⊭ α. Check it against all four combinations of I ⊨ α and I ⊨ β.

▶Check
  • I ⊨ α, I ⊨ β → first disjunct holds → true. Correct.
  • I ⊨ α, I ⊭ β → both fail → false. Correct — the only row where implication should fail.
  • I ⊭ α (either β) → second disjunct holds → true. Correct, vacuous truth.

2.4 Slide 15 asks: why might we not need a semantic rule for α → β at all? Answer it, then identify a smallest set of operators from {¬, ∧, ∨, →, ↔} sufficient to define the rest.

▶Check

Because α → β ≡ ¬α ∨ β, so the clause for → is derivable from those for ¬ and ∨.

Any of {¬, ∧}, {¬, ∨}, or {¬, →} suffices — two is the minimum among this set. (A single operator suffices if you allow NAND or NOR, but neither is in the BNF.)

03

Entailment, validity, satisfiability

~25 min

3.1 Classify as valid, satisfiable-but-not-valid, or unsatisfiable. Justify with an interpretation.

  1. (x ∧ y) → z
  2. x → y
  3. x ∧ ¬x
  4. (x → y) ∨ (y → x)
  5. ¬(x → x)
▶Check
  • (a) Satisfiable, not valid. True under I = ∅; false under I = {x,y}.
  • (b) Satisfiable, not valid. True under I = ∅; false under I = {x}.
  • (c) Unsatisfiable — I ⊨ x and I ⊨ ¬x cannot both hold.
  • (d) Valid. Falsifying needs x ∈ I, y ∉ I for the first disjunct and y ∈ I, x ∉ I for the second. Both cannot hold.
  • (e) Unsatisfiable — x → x is valid, so its negation is never true.

3.2 Slide 16 asks you to label formulae "valid, satisfiable, or unsatisfiable" as though the three were mutually exclusive. They are not. State the actual relationship, and say which two partition the set of all formulae.

▶Check

Every valid formula is also satisfiable, so the three labels overlap. The clean partition is satisfiable versus unsatisfiable.

Validity is a strictly stronger condition sitting inside satisfiable: valid ⊊ satisfiable. And the bridge worth memorising: α is valid ⇔ ¬α is unsatisfiable.

3.3 Decide each entailment. If it holds, argue semantically; if not, give a refuting interpretation.

  1. {x → y, y → z} ⊨ x → z
  2. {x ∨ y} ⊨ x
  3. {x, ¬x} ⊨ y
  4. {x → y} ⊨ ¬x → ¬y
  5. ∅ ⊨ x ∨ ¬x
▶Check
  • (a) Holds. Take any I satisfying both. If I ⊨ x then I ⊨ y then I ⊨ z. If I ⊭ x the conclusion is vacuous.
  • (b) Fails. I = {y} satisfies x ∨ y but not x.
  • (c) Holds, vacuously — no interpretation satisfies both x and ¬x, so there is nothing to check. This is (⊥E) on the semantic side.
  • (d) Fails. I = {y}: premise is F → T, holds; conclusion is T → F, fails.
  • (e) Holds — x ∨ ¬x is valid, so every interpretation satisfies it.

3.4 Prove: S ⊨ α if and only if S ∪ {¬α} is unsatisfiable. Why does this matter for a machine implementation?

▶Check

(⇒) Suppose S ⊨ α and take any I satisfying S ∪ {¬α}. Then I satisfies S, so I ⊨ α; but I ⊨ ¬α means I ⊭ α. Contradiction, so no such I exists.

(⇐) Suppose S ∪ {¬α} is unsatisfiable and take I satisfying S. Then I ⊭ ¬α, so I ⊨ α.

Why it matters: it converts an entailment question — quantified over all interpretations — into a single satisfiability question. A machine can search for one model and fail, rather than enumerate every interpretation. This is the foundation of every refutation-based prover.

4.7 Which rule makes an unrelated β appear, and why is that sound?

α ∧ ¬α  ⊢  β
▶Check
1.α ∧ ¬αhyp

3.¬α(∧Er)(1)
4.⊥(¬E)(2,3)
5.β(⊥E)(4)

(⊥E) makes the unrelated β appear. It is sound because the premise is unsatisfiable: no interpretation satisfies α ∧ ¬α, so "every interpretation satisfying the premises satisfies β" holds vacuously. Compare 3.3(c) — same fact, semantic side.

4.8 Slide 23 recommends working backwards from the conclusion using introduction rules, then forwards using elimination rules. For 4.6, which rule would you apply first under backward reasoning, and why does the shape of the goal determine it?

▶Check

The goal ¬(α ∨ β) is a negation, and the only introduction rule producing a negation is (¬I). So backward reasoning starts by assuming α ∨ β and setting the new goal to ⊥.

Only then do you run out of introduction rules and switch to forward reasoning with (∧El)/(∧Er) on the hypothesis. The shape of the goal picks the rule — that is the whole heuristic.

Classical reasoning

~25 min

5.1 Derive the law of the excluded middle from (PBC). Hint: assume ¬(α ∨ ¬α) and derive ⊥ twice.

⊢  α ∨ ¬α
▶Check
1.[¬(α ∨ ¬α)]1assump
2.[α]2assump
3.α ∨ ¬α(∨Il)(2)
4.⊥(¬E)(3,1)
5.¬α(¬I)2(2–4)
6.α ∨ ¬α(∨Ir)(5)
7.⊥(¬E)(6,1)
8.α ∨ ¬α(PBC)1(1–7)

⊥ is derived twice from the same outer assumption — once via α, once via ¬α. The second derivation is what makes the first one useful.

5.2 Derive double negation elimination from (PBC).

¬¬α  ⊢  α
▶Check
1.¬¬αhyp
2.[¬α]1assump
3.⊥(¬E)(2,1)
4.α(PBC)1(2–3)

5.3 Prove this without any classical rule. What does the asymmetry between this and 5.2 tell you about intuitionistic logic?

α  ⊢  ¬¬α
▶Check
1.αhyp
2.[¬α]1assump
3.⊥(¬E)(1,2)
4.¬¬α(¬I)1(2–3)

This direction needs only (¬I) and (¬E), both intuitionistic. The converse needed (PBC).

So intuitionistically α ⊢ ¬¬α but ¬¬α ⊬ α. Double negation is a strictly weaker statement, and the two become equivalent only classically.

5.4 Using the "proofs as programs" reading on slide 25, explain why (LEM) is the rule an intuitionist objects to. What computational content would a proof of α ∨ ¬α have to carry?

▶Check

Under proofs-as-programs, a proof of α ∨ β is evidence for one disjunct together with a tag saying which.

So a proof of α ∨ ¬α would have to decide, for arbitrary α, whether α or ¬α holds — a universal decision procedure. No such procedure exists in general, so (LEM) asserts the existence of something with no computational content.

(PBC) has the same flaw: it produces evidence for α out of the mere failure of ¬α, without ever constructing it.

06

Broken derivations

~20 min

6.1 The motivating example from slide 29. Is it correct? Name the offending line and the rule condition it violates, then give an interpretation showing the sequent itself does not hold.

(P → Q),  (Q → R)  ⊢  R
1.P → Qhyp
2.Q → Rhyp
3.[P]1assump
4.Q(→E)(1,3)
5.R(→E)(2,4)
6.P → R(→I)1(3–5)
7.R(→E)(6,3)
▶Check

Line 7 is invalid. Assumption [P]1 was opened at line 3 and discharged at line 6 by (→I)1. Once discharged it is out of scope — lines after 6 may not cite it. Line 7 reuses it as though it were still available.

The sequent itself does not hold. Take I = ∅, so P, Q, R are all false. Then P → Q holds vacuously, Q → R holds vacuously, but R is false.

So {P → Q, Q → R} ⊭ R — meaning no correct derivation could exist, and the flaw had to be in the proof rather than in its presentation.

6.2 Find the error.

α ∨ β  ⊢  α
1.α ∨ βhyp
2.[α]1assump
3.α2
4.α(∨E)1(1, 2–3)
▶Check

Line 4 is invalid — two separate problems. (∨E) requires both disjuncts to lead to the same γ; here only the α branch was done, and no [β]2 subproof exists. Second, a β branch could not reach α anyway.

Counterexample: I = {β} satisfies α ∨ β but not α.

6.3 Find the error.

α → β  ⊢  β
1.α → βhyp
2.α(∧El)(1)
3.β(→E)(2,1)
▶Check

Line 2 is invalid. (∧El) applies to a formula whose principal connective is ∧. Line 1's principal connective is →.

The rule simply does not match the shape of the line — there is no conjunction anywhere to eliminate.

6.4 State the general rule that 6.1 and 6.2 both violate, in one sentence, and say why a proof assistant would reject both automatically.

▶Check

An inference rule may only be applied to formulae currently in scope and matching the rule's stated shape.

6.1 breaks scope (a discharged assumption); 6.2 breaks shape (an incomplete (∨E)).

A proof assistant rejects both mechanically because scope is tracked by the context and shape by the type of the rule — neither check requires understanding what the formulae mean, which is exactly why the process can be automated.

This is the point of slide 29. The proof looks fine line by line, and every individual rule name is spelled correctly. What fails is a bookkeeping condition — precisely the kind of thing a human skims past and a checker never does.
07

Metatheory

~15 min

7.1 Define sound and complete for a deductive system, each as a one-line implication between ⊢ and ⊨.

▶Check

Sound: if Θ ⊢ α then Θ ⊨ α. Anything derivable is genuinely entailed — the rules never lie.

Complete: if Θ ⊨ α then Θ ⊢ α. Anything entailed can be derived — the rules miss nothing.

7.2 Describe concretely what a counterexample to soundness would look like. What would you have to exhibit?

▶Check

A set Θ, a formula α, a derivation of Θ ⊢ α, and an interpretation I with I ⊨ Θ but I ⊭ α.

The interpretation is the essential part — a suspicious-looking derivation on its own proves nothing.

7.3 Slide 16 says determining validity is "generally computationally intractable". For propositional logic specifically, what is the complexity of checking satisfiability, and why does that make truth tables impractical for a knowledge base with 200 atoms?

▶Check

Propositional satisfiability is NP-complete (SAT). Validity is the co-NP-complete dual.

A truth table over n atoms has 2n rows, so 200 atoms gives 2200 — vastly more rows than there are atoms in the observable universe.

Hence the shift to derivation and to refutation-based search, which often terminates after exploring a tiny fraction of the space even though the worst case stays exponential.

7.4 Slide 29 quotes Dijkstra: testing shows the presence of bugs but never their absence. Relate this to the difference between satisfiability checking and validity checking on slide 27.

▶Check

Testing samples individual interpretations. Finding one where the system misbehaves proves a bug exists, exactly as finding one satisfying interpretation proves satisfiability. Neither can establish a universal claim by sampling.

Validity checking is the universal claim — true in every interpretation — which is why it needs proof rather than enumeration, and why Dijkstra's remark is the same observation stated for programs.

08

Logic programming

~20 min

8.1 Encode the knowledge base {C, S, C ∧ S → P} in Prolog, and give the query that asks whether P follows.

▶Check
studies_hard.
course_is_easy.
passes :-
    studies_hard,
    course_is_easy.

Query: ?- passes.

8.2 Explain why this is not a legal Prolog clause, and rewrite the information legally.

passes, studies_hard :- course_is_easy.
▶Check

A Prolog clause permits exactly one literal in the head. passes, studies_hard is two, so this is not a Horn clause. Split it:

passes :- course_is_easy.
studies_hard :- course_is_easy.

This is a genuine restriction, not a syntactic inconvenience: Horn clauses cannot express disjunctive conclusions, which is precisely what buys Prolog its efficient resolution strategy.

8.3 Translate each into Prolog, or say why it cannot be a single clause.

  1. α ∧ β → γ
  2. α ∨ β → γ
  3. α → β ∧ γ
  4. α → β ∨ γ
▶Check
  • (a) g :- a, b. — fine, conjunction in the body.
  • (b) g :- a ; b. — fine; equivalently two clauses g :- a. and g :- b.
  • (c) Not a single clause — two heads. Split into b :- a. and c :- a., which is logically equivalent.
  • (d) Not expressible. A disjunctive conclusion is not a Horn clause and has no equivalent set of Horn clauses.

8.4 Given this knowledge base, state the answer to each query.

red(apple).
green(apple).
red(tomato).
fruit(apple).
redFruit(X) :- fruit(X), red(X).
  1. ?- redFruit(apple).
  2. ?- redFruit(tomato).
  3. ?- redFruit(X).
  4. ?- green(tomato).
▶Check
  • (a) true
  • (b) false — red(tomato) holds but fruit(tomato) does not.
  • (c) X = apple
  • (d) false

8.5 Query 8.4(d) returns false, but the knowledge base never says a tomato is not green. What assumption is Prolog making, and what is it called?

▶Check

The closed world assumption: anything not derivable from the knowledge base is taken to be false.

Prolog's negation is negation as failure rather than classical negation — it reports false for "I could not prove this", not for "I proved the negation". For a knowledge base this is a significant modelling commitment, and it is why the lecture defers negation to later.

8.6 Identify which line is the fact and which is the rule, and say what plays the role of the base case of an induction.

sum([], 0).
sum([H|T], N) :- sum(T,M), N is M+H.
▶Check

sum([], 0). is the fact; the second clause is the rule.

The fact plays the role of the base case — the empty list sums to zero — and the rule is the inductive step, defining the sum of [H|T] in terms of the sum of the strictly shorter T.

A recursive Prolog predicate and a proof by induction have the same shape, which is not a coincidence.

Sections 4 and 5 are the ones to do slowly — this lecture's rule set has no derived rules, so modus tollens and De Morgan have to be built from intro/elim pairs. Section 6 is where slide 29 lives, and 6.1 is worth more than its length suggests: the derivation is wrong and the sequent is underivable, and the second fact is how you know the first without hunting. Section 8 is assessable via the labs; 8.5 is the concept that most often gets skipped.
