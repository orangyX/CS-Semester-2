A1recall

Read the specification, not the lecture. Answer from the constraints as written.

  1. Name the DP state and say what its value means. How many states are there, at the constraint limits?
  2. Sample 1 uses $X = 64$ with coins $\{50, 20, 2\}$ and the answer is 5. What does the greedy "take the largest coin that fits" strategy return here, and what does that tell you about the problem?
  3. Sample 4 has $X = 0$. Which line of your program produces that output, and is it a special case?
  4. The denominations are guaranteed distinct and at least 1. Which part of your solution would break if either guarantee were dropped?
(a) The state

$f(x)$ = the fewest coins summing to exactly $x$, or $\infty$ if $x$ is not payable. One coordinate, $x \in [0, X]$, so $X + 1 \le 10^{6} + 1$ states. Each state has up to $N \le 100$ outgoing transitions, giving at most $10^{8}$ transitions at the limits — which is the number that decides whether a Python submission will pass (A5).

The amount alone suffices because coins are unlimited: nothing about the coins already spent constrains what may be spent next. That is exactly the property that would fail if each coin could be used once, which would force a second coordinate and turn this into Part D.

(b) Greedy on sample 1

Greedy takes $50$, then cannot use $20$, so seven $2$s: $50 + 2 \times 7 = 64$, total 8 coins. The optimum is $20 + 20 + 20 + 2 + 2 = 64$, 5 coins.

So greedy is wrong on the very first sample, which is the sample's purpose. Greedy is optimal for canonical systems such as $\{1,5,10,25\}$ — sample-style input 100 4 / 1 5 10 25 gives 4 by both methods — and there is no cheap test for canonicity, so the DP is the only safe approach.

(c) $X = 0$

The base case $f(0) = 0$ produces it, and it is not a special case: the empty multiset pays 0, so the answer follows from the definition. A program that special-cases $X = 0$ is usually one whose base case is wrong.

Watch the input reading, though: with $X = 0$ the DP loop body never executes, so any code that assumes at least one iteration — computing a minimum by initialising from dpt[1], say — will crash or print nothing.

(d) The two guarantees

Distinctness costs nothing: a repeated denomination would simply mean the inner loop does the same work twice. Correctness is unaffected, and de-duplicating is a free constant-factor win.

$c_i \ge 1$ is load-bearing. A coin of value 0 creates a self-loop $x \to x$ in the dependency graph, which stops being acyclic; the recurrence $f(x) = 1 + \min_c f(x-c)$ then has no well-founded evaluation order, and a bottom-up sweep would read $\texttt{dpt}[x]$ while computing $\texttt{dpt}[x]$. A negative coin is worse: it makes the state space infinite in the wrong direction, and the amounts are no longer bounded by $X$. This is the single hypothesis the whole evaluation order rests on and it is worth being able to name.

A2prove

Prove the recurrence and the impossibility handling.

$$f(0) = 0, \qquad f(x) = 1 + \min_{c \in C,\ c \le x} f(x-c) \quad (x \ge 1),$$

with $\min \emptyset = \infty$ and $\infty + 1 = \infty$.

  1. Prove both inequalities, treating the $\infty$ case explicitly rather than waving at it.
  2. Prove the dependency graph is acyclic, with a potential function, and give a valid evaluation order.
  3. The usual implementation replaces $\infty$ with a sentinel integer. State the condition a correct sentinel must satisfy and prove that $X + 1$ works.
  4. Prove that if $f(X) \lt \infty$ then $f(X) \le X$, and use it to justify a tighter sentinel.

For $\le$, exhibit a multiset achieving the right-hand side. For $\ge$, take an optimal multiset for $x$ and remove one coin — any coin. The $\infty$ case is where you must argue that no multiset exists, which is a statement about all of them.

Set-up

Let $S(x)$ be the set of multisets of $C$ summing to exactly $x$, and $f(x) = \min\{|M| : M \in S(x)\}$, with $f(x) = \infty$ when $S(x) = \emptyset$. Since every $c_i \ge 1$, every $M \in S(x)$ with $x \ge 1$ is non-empty.

(a) $\le$

Let $c \in C$ with $c \le x$ and $f(x-c) \lt \infty$, and let $M$ be an optimal multiset for $x - c$. Then $M \cup \{c\}$ sums to $x$, so $f(x) \le |M| + 1 = f(x-c) + 1$. Taking the minimum over all such $c$ gives $f(x) \le 1 + \min_c f(x-c)$.

If no such $c$ exists — either no coin satisfies $c \le x$, or every $f(x-c) = \infty$ — the right-hand side is $\infty$ and the inequality is vacuous.

(a) $\ge$

Suppose $f(x) \lt \infty$ and let $M$ be optimal for $x$. Since $x \ge 1$, $M$ is non-empty; pick any $c \in M$. Then $M \setminus \{c\}$ sums to $x - c \ge 0$, so $f(x-c) \le |M| - 1$, and since $c \le x$ the coin $c$ is in the range of the minimum. Hence

$$1 + \min_{c' \le x} f(x-c') \le 1 + f(x-c) \le |M| = f(x).$$

The $\infty$ case. If $f(x) = \infty$ we must show the right-hand side is also $\infty$ — that is, $f(x-c) = \infty$ for every $c \le x$. Contrapositive: if some $c \le x$ had $f(x-c) \lt \infty$, then by the $\le$ argument $f(x) \lt \infty$. ∎

This case is exactly where a sloppy proof loses marks: it is the direction that says impossibility propagates, and it is what makes IMPOSSIBLE correct rather than merely plausible.

(b) Acyclicity and order

Take $\Phi(x) = x$. Every edge goes $x \to x - c$ with $c \ge 1$, so $\Phi$ strictly decreases along every edge. A cycle would return $\Phi$ to its starting value while strictly decreasing throughout — contradiction. ∎

Since every edge decreases $x$, the order $x = 0, 1, 2, \dots, X$ is valid: each state is computed only after everything it reads.

(c) The sentinel

A sentinel $A$ replacing $\infty$ is correct provided (i) $A$ is strictly greater than every finite $f(x)$ for $x \le X$, so it never wins a minimum it should lose, and (ii) $A + 1$ still exceeds every finite value, so unreachability propagates.

$A = X + 1$ satisfies both. For (i): every finite $f(x)$ uses coins of value $\ge 1$ summing to $x \le X$, so $f(x) \le x \le X \lt A$. For (ii): candidates offered to the minimum are at most $A + 1 = X + 2$, and any candidate at or above $A$ is still above every finite value, so a state stays "at least $A$" exactly when it is unreachable. At the end, test $\texttt{dpt}[X] \ge A$ rather than $= A$, since a state can end up at $A + 1$.

The common error is a sentinel of $0$ or of $-1$: both are below real answers, so they win every minimum and the DP reports 1 for every amount.

(d) The bound $f(X) \le X$

If $f(X) \lt \infty$, an optimal multiset has $k$ coins each of value $\ge 1$ summing to $X$, so $k \le X$. Hence any finite answer is at most $X$.

A tighter sentinel follows: $A = \lceil X / \min_i c_i \rceil + 1$, since a finite answer needs at most $X / \min c_i$ coins. In practice $X+1$ is fine and this refinement matters only when you want the table to fit in a narrow integer type — with all coins $\ge 1000$, say, values fit in 16 bits where $X+1$ would not.

def main():
    data = sys.stdin.read().split()
    X, N = int(data[0]), int(data[1])
    coins = [int(t) for t in data[2:2+N]]

(c) The two bug-catching tests

(d) At the limits

$X = 10^{6}$, $N = 100$ gives $10^{8}$ iterations of the inner loop. In CPython that is roughly 40–100 seconds — too slow for any normal limit. In C or C++ the same loop is well under a second.

What to change, in order of effort: drop coins with $c \gt X$ and de-duplicate (free, sometimes large); swap the loop nesting to for c in coins: for x in range(c, X+1), which hoists the c <= x test into the range bound and removes a branch from the inner loop; use a flat array('i') instead of a list; and if the language must stay Python, express the inner sweep as a vectorised minimum over a NumPy slice, which turns the per-coin pass into one array operation. The last of these keeps the $\Theta(XN)$ work but moves it out of the interpreter.

Case study on cost. Give time, memory, and every route to improving either.

  1. Justify $\Theta(XN)$ time and $\Theta(X)$ memory, distinguishing states from transitions.
  2. Prove that $\Theta(XN)$ is not polynomial in the input size. Give a two-line input on which the algorithm is infeasible.
  3. List every route to reducing time or memory, marking which change the asymptotics.
  4. Suppose the problem asked only whether $X$ is payable, not for the minimum. Does anything get cheaper?
(a) The bounds

States: $X + 1$. Transitions out of each state: at most $N$, one per coin with $c \le x$. Work per transition: one comparison and one addition, $\Theta(1)$. So $\Theta(XN)$ time — a $\Theta$, not an $O$, since both loops run to completion regardless of the input's content.

Memory: one array of $X+1$ integers, $\Theta(X)$. The coins add $\Theta(N)$. Nothing else is retained, and no recursion stack is involved in the bottom-up version.

(b) Pseudo-polynomial

The input is $N + 1$ numbers. Written in binary, $X$ occupies $\lceil \log_2(X+1)\rceil$ bits, so the input length is $L = \Theta(N \log(\max c_i) + \log X)$. But $X = 2^{\Theta(\log X)}$ is exponential in the $\log X$ bits used to write it, so a running time of $XN$ is exponential in $L$. The standard name is pseudo-polynomial: polynomial in the numeric values, exponential in their lengths.

An infeasible two-line input within the stated spirit of the problem (ignoring the $10^{6}$ cap):

1000000000000 2
7 11

Twenty-two characters. The table would need $10^{12}$ cells — about 4 TB even at 4 bytes each — and $2 \times 10^{12}$ operations. The answer, incidentally, is easy: $10^{12} = 7a + 11b$ has solutions, and the minimum coin count is $\lceil 10^{12}/11 \rceil$-ish, obtainable by number theory in microseconds. The DP's difficulty is an artefact of the method, not of the question.

The sliding window deserves the proof: by A2(b) every read is at index $x - c \ge x - \max_i c_i$, so once the sweep has passed $x + \max_i c_i$ the cell at $x$ is dead. Keeping $\max_i c_i + 1$ cells indexed modulo that width is therefore safe — and it destroys the ability to reconstruct the coins, which is the usual price.

(d) Feasibility only

Asymptotically no: it is still $\Theta(XN)$ in the worst case, since you must still determine reachability of $X$ and reachability propagates the same way.

Constants improve a lot, though. The table becomes a bytearray of booleans — 1 byte per cell instead of 28 — and in a language with big integers you can hold the whole reachable set as a single bitmask $R$ and update it with $R \mathrel{|}= R \ll c$ per coin, which does $X$ cells of work in $X/64$ word operations. That is a 64× constant-factor win and turns a $10^{6}$-cell problem into a trivial one.

Why this matters: dropping from "minimum" to "possible" changes the type of the table from integers to bits, and bit-parallel tricks become available. Notice which questions permit that before optimising anything else.

(b) Implementation 
import sys

def main():
    data = sys.stdin.read().split()
    X, N = int(data[0]), int(data[1])
    coins = [int(t) for t in data[2:2+N]]

    SENT = X + 1
    dpt = [SENT] * (X + 1)
    dpt[0] = 0
    for x in range(1, X + 1):
        best = SENT
        for c in coins:
            if c <= x and dpt[x-c] + 1 < best:
                best = dpt[x-c] + 1
        dpt[x] = best

    if dpt[X] >= SENT:
        print("IMPOSSIBLE")
        return

    out = []
    x = X
    while x > 0:
        for c in coins:                       # find any coin on an optimal path
            if c <= x and dpt[x-c] == dpt[x] - 1:
                out.append(c)
                x -= c
                break

    print(dpt[X])
    print(' '.join(map(str, sorted(out))))

(c) Correctness of the walk

The equation. A coin $c$ lies on an optimal path from $x$ exactly when $c \le x$ and $\texttt{dpt}[x-c] = \texttt{dpt}[x] - 1$. Such a $c$ exists whenever $x \ge 1$ and $f(x) \lt \infty$: by A2's $\ge$ direction, some $c \in M$ satisfies $f(x-c) \le f(x)-1$, and by the $\le$ direction $f(x-c) \ge f(x)-1$, so equality holds.

Termination. Each step reduces $x$ by $c \ge 1$, so the loop halts after at most $X$ iterations — and in fact after exactly $f(X)$, since $\texttt{dpt}[x]$ drops by exactly 1 per step from $f(X)$ to 0.

Output size. $\texttt{dpt}$ decreases by one per emitted coin and terminates at $\texttt{dpt}[0] = 0$, so exactly $f(X)$ coins are emitted, and their sum is $X$ because $x$ reaches 0. ∎

This is the step where "$f$ is finite at $X$" is used: the walk is entered only after the IMPOSSIBLE test, and without that guard the inner for could complete without finding a coin, leaving x unchanged and the loop spinning forever. A defensive else: raise on the for is worth writing.

(d) Cost, and when to store choices

Extra time: the walk is $O(f(X) \cdot N)$, since each of the $f(X) \le X$ steps scans the coin list. Extra memory: $\Theta(1)$ beyond the output.

Store the choices instead when $N$ is large and the answer is long — a choice array of one integer per amount turns the walk into $O(f(X))$, removing the factor of $N$, at the cost of doubling the table. At $N = 100$ and $f(X) \approx 10^{5}$ that is $10^{7}$ operations against $10^{5}$, which is worth the memory.

The general rule: store the decision, not a pointer, and only when re-deriving it is expensive. Here re-deriving costs a scan of $N$ coins; in a DP where the branch test is three comparisons, re-deriving is free and storing is waste.

Read the specification carefully — several of its clauses are doing work.

  1. Name the state and say what its value means. Why is the answer $\max_u f(u)$ rather than $f(s)$ for some particular $s$?
  2. Sample 3 has one vertex and no edges. Which clause of the specification forces the output 0, and what would a program that initialises its answer to $-\infty$ print?

(a) The state

$f(u)$ = the maximum total weight of a path starting at $u$. Recurrence $f(u) = \max_{(u,v,w) \in E}\big(f(v) + w\big)$, with the max over an empty set read as 0, so sinks have $f = 0$.

The answer is $\max_u f(u)$ because the problem allows a path to start anywhere. A DAG can have many sources, and the longest path need not begin at any particular one — in sample 2 it begins at vertex 0, which happens to be the only source, but nothing in the specification guarantees that.

The mirror formulation, $g(u) = $ longest path ending at $u$ with $g(u) = \max_{(t,u,w)}(g(t)+w)$, is equally correct and needs the reverse adjacency lists. Pick one and be consistent; mixing them is a common source of confusion when reading other people's solutions.

(b) The single-vertex case

"A single vertex counts as a path of weight 0" forces it. Without that clause you could argue there are no paths at all and the maximum is undefined.

A program initialising its running maximum to $-\infty$ and updating only along edges would print $-\infty$ or crash. Initialise to 0 — or equivalently initialise every $f(u)$ to 0, which the recurrence already does for sinks. The common error is initialising the answer from the first edge, which fails on $E = 0$.

(c) Positive weights

Nowhere, in fact — and that is worth noticing. The correctness of this DP rests entirely on acyclicity, not on the sign of the weights, because the evaluation order comes from a topological sort rather than from any monotonicity of the values.

So zero weights are fine, and negative weights are also fine, which is the striking difference from shortest paths on general graphs, where negative edges break Dijkstra and negative cycles break the problem itself. On a DAG there are no cycles to be negative, so both longest and shortest paths are computable by the same linear-time DP.

The one adjustment: with negative weights the "empty max is 0" convention still gives the right answer for this problem statement, because a single vertex is allowed and has weight 0, so no path of negative total weight can be optimal.

(d) Directedness

Undirected changes the problem completely. Longest path in an undirected graph is NP-hard — it contains the Hamiltonian path problem — and the same graph read as undirected has, for instance, the walk $5 \to 3 \to 2 \to 4 \to 6$, using edges in both directions.

"Directed acyclic" is not decoration; it is the hypothesis that makes a $\Theta(V+E)$ algorithm exist. B6 quantifies exactly what is lost when it is dropped.

B2prove

Prove the recurrence $f(u) = \max_{(u,v,w)}\big(f(v)+w\big)$, with $f(u) = 0$ at sinks, and prove that the values are well-defined.

  1. Prove both inequalities.
  2. Prove $f$ is well-defined, i.e. that the recursion bottoms out. Where is acyclicity used?
  3. Prove that processing vertices in reverse topological order is a valid evaluation order, and that such an order exists.
  4. Show by counterexample that the recurrence is false on a graph with a cycle — not merely unhelpful, but false.
Set-up

Let $P(u)$ be the set of directed paths starting at $u$, and $f(u) = \max_{p \in P(u)} \operatorname{wt}(p)$. The single-vertex path is in $P(u)$ with weight 0, so $P(u) \ne \emptyset$ and $f(u) \ge 0$.

(a) Both directions

$\ge$. For any edge $(u,v,w)$, prepending it to an optimal path from $v$ gives a path from $u$ of weight $f(v) + w$. That is a genuine path — it does not revisit $u$, because a DAG has no path from $v$ back to $u$. Hence $f(u) \ge f(v) + w$ for every out-edge, so $f(u) \ge \max$.

This is where acyclicity is used for the first time: on a graph with cycles, prepending an edge to a path may produce a walk that repeats a vertex, which is not a path.

$\le$. Let $p$ be an optimal path from $u$. If $p$ is the single vertex, $\operatorname{wt}(p) = 0$ and the max over out-edges is $\ge 0$ only if $u$ has an out-edge; if it does not, $u$ is a sink and both sides are 0. Otherwise $p$ starts with some edge $(u,v,w)$ and continues as a path $p'$ from $v$, so

$$f(u) = \operatorname{wt}(p) = w + \operatorname{wt}(p') \le w + f(v) \le \max_{(u,v',w')}\big(f(v') + w'\big). \qquad \blacksquare$$

(b) Well-definedness

Define $\Phi(u)$ = the length in edges of the longest path from $u$, which is finite because a DAG's paths cannot repeat vertices and so have at most $V-1$ edges. Every recursive call goes from $u$ to a successor $v$ with $\Phi(v) \lt \Phi(u)$, so the recursion strictly decreases a non-negative integer and terminates.

Equivalently: the dependency graph is the input graph, which is acyclic by hypothesis, so the recursion is well-founded. Acyclicity is used a second time, and this is the more fundamental use — without it $f$ is not merely hard to compute, it is not defined by the recurrence at all.

(c) Reverse topological order

A topological order is a linear order in which every edge points forwards. Every finite DAG has one: repeatedly remove a vertex of in-degree 0, which must exist, since following in-edges backwards from any vertex must terminate in a DAG.

Processing in reverse topological order means every successor of $u$ is processed before $u$. Since $f(u)$ reads exactly $f(v)$ for successors $v$, every read is of an already-computed value. That is precisely the condition for a valid bottom-up evaluation order. ∎

Sample 1 admits several topological orders — $0,1,2,3,4,5,6$ and $0,2,1,4,3,6,5$ among them, ten in total for that graph. Any of them, reversed, works; the DP does not care which.

(d) With a cycle, the recurrence is false

Take two vertices and edges $(0,1,1)$ and $(1,0,1)$. The genuine longest path from 0 is $0 \to 1$, weight 1. But the recurrence asserts $f(0) = f(1) + 1$ and $f(1) = f(0) + 1$, which has no finite solution — substituting gives $f(0) = f(0) + 2$.

So the recurrence is not a difficult-to-evaluate description of the right answer; it is an inconsistent system. A program that ran it anyway would loop forever, or with memoisation would deadlock on a state it is already computing.

The moral: "overlapping subproblems" is a licence to memoise only once the dependency graph is acyclic. Check acyclicity before writing the recurrence, not after the program hangs.

(a) The bound, and where $O(E)$ fails

Kahn's algorithm touches each vertex once and each edge once: $\Theta(V+E)$. The DP pass then visits each vertex once and each edge once: $\Theta(V+E)$ again. Initialising adj, indeg and f is $\Theta(V)$. Total $\Theta(V+E)$.

Where $O(E)$ is false. Take the input 100000 0 — a hundred thousand isolated vertices and no edges. Then $E = 0$, so $O(E) = O(1)$, yet any correct program must at minimum read $V$, allocate the arrays, and output $\max_u f(u) = 0$, which is $\Theta(V)$ work. The stated bound is off by a factor of $V$, unbounded as $V$ grows.

The bound is harmless whenever $E = \Omega(V)$, which is the usual case and is presumably why the slide gets away with it. It is still worth fixing: $\Theta(V+E)$ is no harder to write and is true.

(b) Memory

Adjacency lists: $\Theta(V + E)$ — one list object per vertex plus one entry per edge. B6prove

Each claim is false. Name the dropped hypothesis or confused concept, and give an explicit counterexample — as a small input in the problem's own format where possible.

  1. "Longest path is just shortest path with the weights negated, so run Dijkstra on $-w$."
  2. "The longest path starts at a source and ends at a sink, so it is enough to try each source."
  3. "The longest path in edges and the longest path in weight visit the same vertices, since all weights are positive."
  4. "The DP is $\Theta(V+E)$ on any graph; acyclicity only makes it easier to find the evaluation order."
  5. "Since $f(u) \ge f(v)$ whenever there is an edge $u \to v$, sorting the vertices by $f$ gives a topological order."
(a)

Negation destroys Dijkstra's hypothesis. Dijkstra requires non-negative weights; after negation every weight is non-positive, and its greedy "closest unvisited vertex is final" argument fails immediately.

Counterexample: 3 3 / 0 1 1 / 1 2 1 / 0 2 1. Negated, Dijkstra from 0 settles vertex 2 at $-1$ via the direct edge before discovering $0 \to 1 \to 2$ at $-2$. It reports 1 where the answer is 2.

Bellman–Ford would work on a DAG with negative weights, but at $\Theta(VE)$ — far worse than the $\Theta(V+E)$ available here. Negating and reaching for a shortest-path algorithm is a step backwards on both counts.

(b)

True for the start, false as stated for the method. A longest path can indeed be extended to start at a source and end at a sink when all weights are positive. But "try each source" suggests running a separate search per source, which is $\Theta(S(V+E))$ for $S$ sources — quadratic on a graph with many sources — where the DP computes all of them in one pass.

And with zero or negative weights permitted, the claim is false outright: 2 1 / 0 1 -5 has its longest path at vertex 0 alone, weight 0, which starts at a source and ends there, not at the sink.

The test 5 4 / 1 0 100 / 2 3 1 / 3 4 1 / 2 4 1 from B3 makes the practical version of the point: the answer is at vertex 1, and a program that only starts from vertex 0 prints 0.

(c)

Confuses two different objectives. Positive weights guarantee that extending a path never hurts; they do not make edge count and total weight the same ordering.

Counterexample, which is B3's last extra test: 4 4 / 0 1 1 / 1 2 1 / 0 2 3 / 2 3 1. The route $0 \to 1 \to 2 \to 3$ has three edges and weight 3; the route $0 \to 2 \to 3$ has two edges and weight 4. The heaviest path is the one with fewer edges, and the two objectives do not even agree on which vertices are visited — vertex 1 is on one and not the other.

(d)

Drops the hypothesis that makes the problem tractable at all. On a general directed graph, longest simple path is NP-hard: it contains Hamiltonian path as the special case "is there a path of $V-1$ edges?". No $\Theta(V+E)$ algorithm exists unless P $=$ NP.

Counterexample to the recurrence itself is B2(d): with a two-cycle the equations have no finite solution, so there is nothing for a $\Theta(V+E)$ pass to compute. Acyclicity is not a convenience for ordering; it is what makes the values exist.

(e)

Confuses a necessary condition with a sufficient one. It is true that $f(u) \ge f(v) + w \gt f(v)$ along an edge with $w \ge 1$, so $f$ is strictly decreasing along edges and sorting by $f$ descending puts every edge's tail before its head. So far the claim looks right — and it is, for strictly positive weights.

It breaks as soon as weights may be 0, which B1(c) established the algorithm otherwise tolerates. Counterexample: 3 2 / 0 1 0 / 1 2 0 gives $f = [0,0,0]$, and sorting by $f$ gives no information at all — any of the six orders is equally consistent, and four of them are not topological.

The moral: a DP's values often correlate with the evaluation order, and using them as the order is a shortcut that works until a tie appears. Compute the order from the structure, not from the answers.

(a) Subsequence versus substring

$Z = \langle z_1,\dots,z_k\rangle$ is a subsequence of $X = \langle x_1,\dots,x_m\rangle$ if there are indices $i_1 \lt i_2 \lt \dots \lt i_k$ with $z_t = x_{i_t}$ for every $t$. Equivalently: delete any characters, keep the rest in order.

A substring additionally requires the indices to be consecutive: $i_{t+1} = i_t + 1$. That is the one clause that differs — "strictly increasing" is strengthened to "increasing by exactly one".

The common error is solving longest common substring by mistake. It is a different DP: on a mismatch the value resets to 0 rather than taking a max of neighbours, and the answer is the maximum over all cells rather than the corner cell. Both run in $\Theta(mn)$, and both compile.

(b) The state

$f(i,j)$ = the LCS length of the prefixes $X_i = x_1..x_i$ and $Y_j = y_1..y_j$. Base case $f(i,0) = f(0,j) = 0$, which is forced by the definition — the empty sequence is a subsequence of everything — rather than chosen.

Not unique. Sample 1 has exactly three longest common subsequences — BCAB, BCBA and BDAB, all of length 4. The length is unique, being a maximum over a finite set.

That is exactly why the output specification asks for the length: a judge can compare a single integer exactly. C2prove

Prove the recurrence.

$$f(i,j) = \begin{cases} 0 & i = 0 \text{ or } j = 0,\\[2pt] f(i-1,j-1) + 1 & x_i = y_j,\\[2pt] \max\big(f(i-1,j),\ f(i,j-1)\big) & \text{otherwise.}\end{cases}$$

  1. Matching case. Prove that when $x_i = y_j$, some LCS of $X_i$ and $Y_j$ ends with that character, and deduce the $+1$ line. Identify the exchange argument.
  2. Mismatching case. Prove both inequalities. The lecture says "at least one of the final elements is excluded" — make that precise and prove it.
  3. Prove the dependency graph is a DAG with a potential function, and say why "$i$ decreases" is not by itself enough here.
  4. Give an input where $f(m,n) \gt f(m-1,n-1)$ despite $x_m \ne y_n$, and say which tempting shortcut it kills.

For (a), take a maximum-length common subsequence that does not end in $c = x_i = y_j$ and derive a contradiction by appending $c$ to it. For (c), neither coordinate decreases on every edge — find a quantity that does.

(a) The matching case

Write $c = x_i = y_j$. Let $Z$ be a common subsequence of $X_i, Y_j$ of maximum length $k$, with witnesses $i_1 \lt \dots \lt i_k$ and $j_1 \lt \dots \lt j_k$.

Suppose $z_k \ne c$. Then $i_k \ne i$ and $j_k \ne j$, so $i_k \lt i$ and $j_k \lt j$: positions $i$ and $j$ are unused. Appending gives $Z' = \langle z_1,\dots,z_k,c\rangle$, a common subsequence — extend the witnesses by $i$ and $j$, both still strictly increasing — of length $k+1$. That contradicts maximality. So every maximum-length common subsequence ends with $c$.

Deducing the line. $\ge$: take an LCS $W$ of $X_{i-1}, Y_{j-1}$; then $W\cdot c$ is a common subsequence of $X_i, Y_j$, so $f(i,j) \ge f(i-1,j-1)+1$. $\le$: take an LCS $Z$ of $X_i,Y_j$, which ends in $c$ and may be witnessed with $i_k = i$, $j_k = j$; deleting the last character gives a common subsequence of $X_{i-1},Y_{j-1}$ of length $k-1$. ∎

The exchange is the "suppose $z_k \ne c$" paragraph — it rewrites any optimal solution into one of the shape the recurrence assumes, and it is the only place in the whole proof where an optimal solution is modified rather than merely cut.

(b) The mismatching case

$\ge$. Every common subsequence of $X_{i-1},Y_j$ is one of $X_i,Y_j$ — same witnesses, since $X_{i-1}$ is a prefix. So $f(i,j) \ge f(i-1,j)$, and symmetrically $\ge f(i,j-1)$. This direction never uses the hypothesis; it is plain monotonicity.

$\le$. Let $Z$ be an LCS of $X_i,Y_j$, length $k$. Case 1: $i_k \lt i$. Then $Z$ lies in $X_{i-1}$ and $Y_j$, so $k \le f(i-1,j)$. Case 2: $i_k = i$, so $z_k = x_i$. Since $x_i \ne y_j$ we get $z_k \ne y_j$, hence $j_k \ne j$, hence $j_k \lt j$, so $Z$ lies in $X_i$ and $Y_{j-1}$ and $k \le f(i,j-1)$. Exhaustive, so $k \le \max$. ∎

The hypothesis $x_i \ne y_j$ is used exactly once, in Case 2, to conclude $j_k \ne j$.

Making the lecture's phrase precise. "At least one of the final elements is excluded" means: for every LCS witness, either position $i$ of $X$ is unused by the $X$-map or position $j$ of $Y$ is unused by the $Y$-map. If both were used, the last element of $Z$ would equal $x_i$ from one side and $y_j$ from the other, forcing $x_i = y_j$. Note it is the position that goes unused, not the character — B appears in LCSs of sample 1 even though it is $X$'s last character.

(c) Acyclicity

Take $\Phi(i,j) = i + j$. Edges go to $(i-1,j-1)$, $(i-1,j)$, $(i,j-1)$, dropping $\Phi$ by 2, 1, 1 — strictly, in every case. A cycle would return $\Phi$ to its start while strictly decreasing throughout. ∎

"$i$ decreases" is not enough because the mismatching case has an edge to $(i,j-1)$, on which $i$ is unchanged. (a) The naive bound

There are $2^{m}$ index subsets of $X$, and the algorithm examines each. (a) Problem and state

$$\max_{S \subseteq \{1..N\}} \sum_{i \in S} v_i \quad \text{subject to} \quad \sum_{i \in S} w_i \le W.$$

$f(i,w)$ = the maximum value obtainable from items $1..i$ with capacity $w$. Base cases $f(0,w) = 0$ and $f(i,0) = 0$, both forced: no items means no value, and since every $w_i \ge 1$, zero capacity means nothing fits.

At the limits, $(1000+1)(10^{5}+1) \approx 10^{8}$ states. That is the number that decides everything about this problem — $10^{8}$ operations is already slow, and $10^{8}$ table cells is impossible. D5 and D6 are about both halves of that.

(b) Why the item index

Because "which items are still available" must be in the state, and ordering the items lets a single index encode it: at $(i-1, \cdot)$ you can never return to item $i$.

Drop it and the recurrence becomes $f(w) = \max_i\big(f(w-w_i)+v_i\big)$, which allows an item to be reused. That is the unbounded knapsack — a different problem with a different answer, and it is exactly Part A's coin change with a $\max$ over values instead of a $\min$ over counts.

The discriminating question for any DP formulation: does the optimal solution to a subproblem depend on what the rest of the solution consumed? Here it does, so that dependency must appear in the state.

(c) The neighbours

Fractional: take any $x_i \in [0,1]$ of item $i$, receiving $x_i v_i$. Unbounded: take each item any number of times.

Only fractional is greedy-solvable, by taking items in decreasing $v_i/w_i$ and splitting the last one. The exchange argument works precisely because a partial item absorbs the leftover capacity, so no capacity is ever wasted. Under integrality the leftover is simply lost, and the exchange has nothing to trade with. Both 0-1 and unbounded knapsack are NP-hard.

Prove the recurrence, for $i \ge 1$ and $w \ge 1$:

$$f(i,w) = \begin{cases} f(i-1,w) & w \lt w_i,\\[2pt] \max\big(f(i-1,w),\ f(i-1,\,w-w_i) + v_i\big) & \text{otherwise.}\end{cases}$$

(a) The main case

$\ge$. Both candidates are achievable. An optimal $S \subseteq \{1..i-1\}$ of weight $\le w$ is also a subset of $\{1..i\}$ of weight $\le w$, giving $f(i,w) \ge f(i-1,w)$. And if $T \subseteq \{1..i-1\}$ is optimal at capacity $w - w_i$, then $T \cup \{i\}$ has weight $\le w$ and value $f(i-1,w-w_i)+v_i$.

The step enforcing "at most once" is "$T$ draws only from $\{1,\dots,i-1\}$", so $i \notin T$. That is supplied by the state's first coordinate, not by any check in the code — which is why an implementation that reads the wrong row silently solves the unbounded problem instead.

$\le$. Let $S \subseteq \{1..i\}$ be optimal at capacity $w$. If $i \notin S$ then $S \subseteq \{1..i-1\}$ with weight $\le w$, so $\operatorname{val}(S) \le f(i-1,w)$. If $i \in S$ then $S \setminus \{i\}$ has weight $\le w - w_i$, so $\operatorname{val}(S) - v_i \le f(i-1,w-w_i)$. Either way $\operatorname{val}(S) \le \max$. ∎

The cut is "remove item $i$"; the paste is "substitute an optimal solution to the smaller instance", legitimate because removing an item only frees capacity.

(b) The guard

If $w \lt w_i$, item $i$ is in no feasible subset — including it forces weight $\ge w_i \gt w$. So every feasible $S \subseteq \{1..i\}$ omits $i$, the two problems have identical feasible sets, and $f(i,w) = f(i-1,w)$.

Not merely an optimisation. Without the guard, $\texttt{dpt}[i-1][w-w_i]$ has a negative index, which in Python wraps silently to the end of the row and returns the value at full capacity. No exception, no warning, and a plausible-looking number. Sample 3 exists precisely to catch this: with $W = 5$ and one item of weight 6, the unguarded code computes $\texttt{dpt}[0][-1] + 100 = 100$ and prints 100 where the answer is 0.

(c) Acyclicity

$\Phi(i,w) = i$ works: every edge goes from $(i,w)$ to $(i-1,\cdot)$, so $\Phi$ drops by exactly 1 on every edge. A cycle would return $\Phi$ to its start while strictly decreasing. ∎

Contrast Part C, where the mismatching case has an edge to $(i,j-1)$ on which $i$ is unchanged, so $i+j$ was needed instead. Knapsack's graph is strictly layered by $i$: all edges cross from layer $i$ to layer $i-1$, none stay within a layer. That is a stronger structure, and it is exactly what makes the one-row optimisation of D6 take the form it does.

(d) Monotone, but not Lipschitz

Non-decreasing in $w$: a subset feasible at capacity $w$ is feasible at $w+1$, so the feasible set grows and the maximum cannot fall. Non-decreasing in $i$: a subset of $\{1..i-1\}$ is a subset of $\{1..i\}$. ∎

No bound on the jump. Take $W$ and a single item of weight $W$ and value $V$. Then $f(1,W-1) = 0$ and $f(1,W) = V$, a jump of $V$, which the input chooses freely. The largest possible jump is exactly $\max_i v_i$, since one extra unit of capacity can bring at most one further item into play — but that item's value is unbounded.

This is the structural difference from LCS, whose adjacent entries differ by at most 1. It rules out difference encoding and bit-packed rows here, and it is the same distinction that makes LCS polynomial while knapsack is only pseudo-polynomial: the range of table values is $\Theta(\min(m,n))$ in one case and $\Theta(\sum v_i)$ in the other.

(a) Pseudo-polynomial

Written in binary, $W$ occupies $\lceil\log_2(W+1)\rceil$ bits, so the input length is $L = \Theta(N \log(\max(w_i,v_i)) + \log W)$. Since $W = 2^{\Theta(\log W)}$, a running time of $NW$ is exponential in $L$. The name is pseudo-polynomial: polynomial in the numeric values, exponential in their lengths. And since 0-1 knapsack is NP-hard, a genuinely polynomial exact algorithm would settle P versus NP.

A short infeasible input. Take $N = 100$ items and $W = 10^{15}$ — about a kilobyte of text. The table would have $10^{17}$ cells. (b) The value-indexed formulation

State: $h(i,v)$ = the minimum total weight of a subset of items $1..i$ with total value exactly $v$, or $\infty$ if no such subset exists, for $v \in [0, V]$ with $V = \sum_i v_i$.

Base: $h(0,0) = 0$, and $h(0,v) = \infty$ for $v \ge 1$.

Why infinity. The two formulations differ in what the base case means. In the weight formulation, $f(0,w) = 0$ is a genuine achievable answer — take nothing, get value 0, and it fits — so every state is feasible and no sentinel is needed. In the value formulation, "achieve value $v$ using no items" is impossible for $v \ge 1$; it is not a zero-weight solution but no solution. Using 0 would claim any value is free and the minimum would propagate 0 across the row. The sentinel must be a value no real answer can take — for a minimisation, above every achievable weight, so $\infty$ or $1 + \sum_i w_i$ both work and $0$ does not. Same trap as Part A's sentinel.

(a) Version 1 is 0-1

Invariant: after the outer loop has processed items $1..i$, $\texttt{dpt}[w] = f(i,w)$ for every $w$. Initially the row is all zeros, matching $f(0,w) = 0$.

Maintenance. Suppose the row holds row $i-1$. Sweeping $w$ from $W$ down to $w_i$, the update at $w$ reads cells $w$ and $w - w_i$. The descending sweep has written only cells with index $\gt w$; and $w - w_i \lt w$ because $w_i \ge 1$, while $w$ itself is read before it is written. So both cells read still hold row $i-1$ values: $f(i-1,w)$ and $f(i-1,w-w_i)$, which are exactly the two arguments of the recurrence. The assignment writes $f(i,w)$. ✓ ∎

The cell whose survival the descending order guarantees is $\texttt{dpt}[w-w_i]$, the one at smaller capacity. An ascending sweep would have overwritten it before reaching $w$.

(b) Version 2 is unbounded

Let $g(i,w)$ be the optimum using items $1..i$ with unlimited copies. Its recurrence recurses on $g(i, w - w_i)$ — the same row — because after taking one copy you may take another:

$$g(i,w) = \max\big(g(i-1,w),\ g(i,\,w-w_i)+v_i\big).$$

Invariant: during the sweep at capacity $w$, the row holds $g(i,t)$ for $t \lt w$ and $g(i-1,t)$ for $t \ge w$. The update at $w$ reads $\texttt{dpt}[w] = g(i-1,w)$, not yet reached, and $\texttt{dpt}[w-w_i] = g(i,w-w_i)$, already overwritten — exactly the two arguments above. So it writes $g(i,w)$. ✓ ∎

So version 2 is not a wrong answer to Problem D; it is the right answer to a different problem, which is a far more dangerous kind of bug.

(d) The loop bound, the memory, and the cost

Why start at wi. For $w \lt w_i$ the recurrence gives $f(i,w) = f(i-1,w)$, and the row already holds that, so the correct action is to do nothing. range(wi, W+1) encodes the guard of D2(b) as a loop bound. Starting at 1 without an if would evaluate dpt[w-wi] with a negative index and wrap — the silent failure of D3(c), now hidden inside the optimised version where it is even harder to spot. Encoding a guard as a loop bound is strictly safer than encoding it as a condition, since an omitted bound is a visible change while an omitted condition still runs.

Memory. $\Theta(W)$ instead of $\Theta(NW)$ — a factor of $N$. At the constraint limits: $10^{8}$ cells and 2.6 GiB become $10^{5}$ cells and about 2.7 MiB. The program now fits any reasonable limit, and time is the only remaining obstacle.

What is given up. The traceback of D4(d), which needs two adjacent rows at capacities determined by the walk — and every row but the last has been overwritten in place. That is not merely inconvenient: the information no longer exists in the program's state, and it cannot be recovered from the final row, since two different item sets can produce identical final rows. The repair is divide and conquer over the items in the Hirschberg style, splitting the capacity optimally between the two halves, which recovers the item set in $\Theta(N+W)$ memory at a small factor in time. So the general remark that traceback "becomes impossible" after memory optimisation is better read as "becomes harder, and the standard repair is divide and conquer".

Getting the state right is the whole difficulty here.

  1. Explain why $f(i) =$ "the length of the longest increasing subsequence within $a_1..a_i$" does not support a recurrence.

(a) Why the obvious state fails

Because it does not record what may be appended next. Suppose $f(i) = 3$; to decide whether $a_{i+1}$ extends the best subsequence you need to know that subsequence's last element, and the state does not carry it. Two sequences with the same $f(i)$ can behave completely differently — 1 2 3 and 1 2 100 both have $f(3) = 3$, and appending 50 extends the first and not the second.

Formally, optimal substructure fails: an optimal solution to the prefix subproblem is not necessarily extendable into an optimal solution to the whole, so the greedy-looking recurrence $f(i+1) = f(i) + [\text{extendable}]$ is not even well defined.

(b) The state that works

$f(i)$ = the length of the longest strictly increasing subsequence ending at index $i$, i.e. using $a_i$ as its final element.

$$f(i) = 1 + \max\{f(j) : j \lt i,\ a_j \lt a_i\},$$

with the max over an empty set read as 0, so $f(i) \ge 1$ always.

The answer is $\max_i f(i)$, not $f(n)$, because the optimal subsequence need not end at the last element — in sample 1 it ends at index 6 (the value 7) or index 7 or 8, and $f(8) = 4$ only by luck. Pinning the endpoint is the same move that gives knapsack its item index and gives Part B's longest path its "starting at $u$" formulation: make the state carry the thing the next decision depends on.

(c) "Strictly"

"Strictly increasing" forces answer 1 on 2 2 2 2: no two equal elements may both appear. Without it — the non-decreasing variant — the answer would be 4.

Sample 3 exists entirely to separate the two. In code the difference is one comparison, a[j] < a[i] against a[j] <= a[i], or in the fast version bisect_left against bisect_right. The common error is a single character, and it passes samples 1 and 2, both of which have distinct elements.

(d) The three edge conditions

Negative values: nothing to think about. The DP compares values and never assumes a sign or a lower bound, and the fast version compares them too.

Repeats: the whole content of (c). This is the one that matters.

$n = 1$: the answer is 1, which falls out of $f(1) = 1$. Watch the input parsing rather than the DP — a program that reads the second line by splitting on spaces handles it fine, and one that assumes at least two tokens does not.

E2prove

Prove the recurrence of E1(b), and prove the reduction to LCS.

  1. Prove $f(i) = 1 + \max\{f(j) : j \lt i,\ a_j \lt a_i\}$, both directions.
  2. Prove that $\max_i f(i)$ is the answer.
  3. Let $b$ be the sorted list of distinct values occurring in $a$. Prove $\operatorname{LIS}(a) = \operatorname{LCS}(a, b)$.
  4. Show by counterexample that the reduction fails if duplicates are left in $b$.
(a) The recurrence

$\ge$. Let $j \lt i$ with $a_j \lt a_i$, and let $Z$ be a longest increasing subsequence ending at $j$, of length $f(j)$. Appending $a_i$ gives an increasing subsequence ending at $i$: the indices remain increasing since $j \lt i$, and the values remain strictly increasing since $a_j \lt a_i$ and $a_j$ was $Z$'s last element. So $f(i) \ge f(j) + 1$ for every such $j$, hence $f(i) \ge 1 + \max$.

This is exactly where "$a_j$ was $Z$'s last element" is used — it is what the state's endpoint pinning buys, and without it the appended value could be smaller than something already in $Z$.

$\le$. Let $Z$ be a longest increasing subsequence ending at $i$, of length $k$. If $k = 1$, then $Z = \langle a_i \rangle$ and the right-hand side is at least $1 + 0 = 1$. If $k \ge 2$, let $j$ be the index of $Z$'s second-to-last element; then $j \lt i$ and $a_j \lt a_i$, and $Z$ minus its last element is an increasing subsequence ending at $j$ of length $k-1$, so $f(j) \ge k-1$. Hence $1 + \max \ge 1 + f(j) \ge k = f(i)$. ∎

(b) The answer

Every non-empty increasing subsequence ends at some index $i$, so its length is at most $f(i) \le \max_i f(i)$. Conversely each $f(i)$ is achieved by an actual subsequence. So the maximum over $i$ is exactly the longest. (With $n \ge 1$ there is always at least one, of length 1, so no empty-max case arises.) ∎

(c) The reduction

A common subsequence of $a$ and $b$ is a sequence appearing in order in both. Appearing in order in $b$ means strictly increasing, because $b$ is sorted and its entries are distinct — so no value can be used twice and the values must ascend.

Hence: {common subsequences of $a$ and $b$} $=$ {strictly increasing subsequences of $a$}. The two sets are equal, so their maximum lengths are equal. ∎

Cost: $|b| \le n$, so this is $\Theta(n^{2})$ time and, with the one-row LCS of C6, $\Theta(n)$ memory — no better than (a) asymptotically. The reduction's value is conceptual: it shows the two problems are the same problem in disguise, which is the sort of observation an exam rewards.

(d) Duplicates break it

Take $a = \langle 2,2 \rangle$. With duplicates removed, $b = \langle 2 \rangle$ and $\operatorname{LCS}(a,b) = 1$ — correct.

With duplicates left in, $b = \langle 2,2 \rangle$, and now $\langle 2,2 \rangle$ is a subsequence of $b$ as well as of $a$, so $\operatorname{LCS} = 2$. But $\langle 2,2\rangle$ is not strictly increasing, so the reduction over-counts. On sample 3 it would report 4 against the correct 1.

Sorting alone is not enough; de-duplication is the step that encodes strictness. If you wanted the non-decreasing variant instead, keeping the duplicates in $b$ is precisely the right change — which is a satisfying confirmation that the two variants differ in exactly one place, wherever you look at them from.

    tails = []
    for x in a:
        k = bisect_left(tails, x)       # first index with tails[k] >= x

            tails.append(x)             # x extends the longest run so far
        else:

$n$ iterations, each an $O(\log n)$ binary search and an $O(1)$ write: $O(n\log n)$ time, $\Theta(n)$ memory. At $n = 2\times10^{5}$ that is about $3.5 \times 10^{6}$ comparisons — instant.

(b) The invariant

After processing a prefix of $a$: tails is strictly increasing, its length is the LIS length of that prefix, and for each $k$, tails[k] is the smallest value that can end a strictly increasing subsequence of length $k+1$ within that prefix.

Sortedness. Initially empty. An append places $x$ at the end, and $x$ exceeds every existing entry because bisect_left returned len(tails), meaning no entry is $\ge x$. A replacement writes $x$ at position $k$ where tails[k-1] < x <= tails[k], so the array stays sorted; and it stays strictly sorted because the new $x$ is strictly greater than tails[k-1]. ✓

Achievability. On an append, a subsequence of length $k$ ending at tails[k-1] exists by induction and tails[k-1] < x, so appending $x$ gives one of length $k+1$. On a replacement at position $k$, the same argument with tails[k-1] < x gives a length-$(k{+}1)$ subsequence ending at $x$, and $x \le$ the old tails[k], so the entry only improves. ✓

Minimality. Suppose some subsequence of length $k+1$ ended at a value $y \lt$ tails[k]. Its element at position $k$ would have been processed earlier, and at that moment bisect_left would have placed it at index $k$ or lower, making tails[k] at most $y$. Contradiction. ✓

Length. tails grows by one exactly when the current element extends the longest achievable run, so its length tracks the prefix's LIS length. ∎

(c) Which bisect

bisect_left. It returns the first index with tails[k] >= x, so a value equal to an existing tail replaces it rather than extending past it — which is exactly what strictness demands: two equal values cannot both be in one subsequence.

bisect_right returns the first index with tails[k] > x, so an equal value appends and lengthens the run: that solves the non-decreasing variant. One letter, two problems. Sample 3 separates them — bisect_left gives 1, bisect_right gives 4 — which is why that sample is in the problem at all.

(d) tails is not the answer

No. On $a = \langle 2, 5, 3\rangle$: after 2, tails = [2]; after 5, [2,5]; after 3, bisect_left gives index 1 so tails = [2,3]. The length 2 is correct, and $\langle 2,3\rangle$ is an increasing subsequence here — try instead $a = \langle 1, 6, 7, 2, 3\rangle$: the final tails is $[1,2,3]$, and $\langle 1,2,3\rangle$ is indeed a subsequence. The failure is subtler: on $a = \langle 5, 6, 1\rangle$ the final tails is $[1,6]$, which is not a subsequence of $a$ at all, since 1 occurs after 6.

Only the length of tails is meaningful. Printing it as the subsequence is the standard mistake. Recovering an actual subsequence needs a parallel array recording, for each element, the index of the predecessor that was at tails[k-1] when it was placed — the same "store the decision" pattern as Part A's coin array, and it costs $\Theta(n)$ extra memory.

Each claim is false. Name the confusion and give a counterexample, as a small input in the problem's format.

Confuses "the last state computed" with "the state holding the answer". $f(n)$ is the longest increasing subsequence ending at $a_n$, which is only the global answer when the optimum happens to end there.

Counterexample: 3 / 1 2 0. Here $f = \langle 1,2,1\rangle$, the answer is 2, and $f(n) = 1$. Neither of samples 1 and 2 catches this, per E4(d).

(b)

Drops the de-duplication step, which is what encodes strictness (E2(d)).

Counterexample: 4 / 2 2 2 2, which is sample 3. Sorting gives $b = \langle 2,2,2,2\rangle$ and $\operatorname{LCS}(a,b) = 4$, against the correct answer 1. The claim fails on a sample.

(c)

Confuses a covering with a partition, and misremembers the Erdős–Szekeres theorem. What is true is a counting statement: a sequence of more than $pq$ elements contains an increasing subsequence of length $p+1$ or a decreasing one of length $q+1$. Nothing says the two cover the array.

Counterexample: 5 / 3 1 4 1 5. The LIS is $\langle 1,4,5\rangle$ or $\langle 3,4,5\rangle$ (length 3) and the longest strictly decreasing subsequence is $\langle 3,1\rangle$ or $\langle 4,1\rangle$ (length 2). Take LIS $\langle 3,4,5\rangle$ at indices 1,3,5 and LDS $\langle 4,1\rangle$ at indices 3,4: together they miss index 2 entirely, and they overlap at index 3. Neither a cover nor a partition.

(d)

Confuses a correct length with a correct witness. The method is greedy in its maintenance of tails, but tails is a record of best possible endings, assembled from elements encountered at different times, not a subsequence.

Counterexample: 3 / 5 6 1. Final tails is $[1,6]$, which is not a subsequence of the input at all — 1 occurs after 6. The length 2 is right; the array is not an answer. Recovering the witness needs predecessor indices, per E5(d).

(e)

Confuses a reduction's cost with a lower bound. A reduction from A to B shows A is no harder than B plus the reduction's cost; it says nothing about A being as hard as B. To conclude a lower bound you would need a reduction in the other direction.

Counterexample: E5's algorithm, which runs in $O(n\log n)$. And in fact the general LCS hardness does not transfer because the LCS instances produced by the reduction are highly special — one of the two sequences is sorted and distinct — which is exactly the structure the patience method exploits.

The moral: reductions travel upwards for upper bounds and downwards for lower bounds, and mixing the directions is one of the most common errors in complexity arguments.

F2prove

Prove the recurrence:

$$d(i,j) = \begin{cases} d(i-1,j-1) & x_i = y_j,\\[2pt] 1 + \min\big(d(i-1,j),\ d(i,j-1),\ d(i-1,j-1)\big) & \text{otherwise,}\end{cases}$$

with $d(i,0) = i$ and $d(0,j) = j$.

  1. Prove $\le$ and $\ge$ for the mismatching case.
  2. Prove the matching case — in particular, prove that when $x_i = y_j$ it is safe to match rather than considering the other three options.
  3. Prove the base cases, i.e. that $d(i,0) = i$ exactly and not merely at most $i$.
  4. Prove $|d(i,j) - d(i-1,j)| \le 1$, and use it to bound the number of bits needed per table cell.

For (b), take an optimal script and argue that if it does not match $x_i$ with $y_j$, it can be rewritten into one that does, without getting longer. That is an exchange argument, and it is the only one in this proof.

Set-up

An edit script is a sequence of insertions, deletions and substitutions; $d(i,j)$ is the least length of a script taking $X_i$ to $Y_j$. Every script can be normalised to process the strings left to right, since operations on disjoint positions commute.

(a) The mismatching case

$\le$. Three constructions. Take an optimal script for $(i-1,j)$ and prepend a deletion of $x_i$: length $d(i-1,j)+1$. Take an optimal script for $(i,j-1)$ and append an insertion of $y_j$: length $d(i,j-1)+1$. Take an optimal script for $(i-1,j-1)$ and add a substitution $x_i \to y_j$: length $d(i-1,j-1)+1$. All three are valid scripts for $(i,j)$, so $d(i,j)$ is at most the minimum. ✓

$\ge$. Let $S$ be an optimal script for $(i,j)$. Consider what $S$ does with the final character $x_i$ and the final character $y_j$. Three exhaustive cases:

— $S$ deletes $x_i$. Removing that operation leaves a script from $X_{i-1}$ to $Y_j$, so $|S| - 1 \ge d(i-1,j)$.

— $S$ inserts $y_j$ as the last character. Removing it leaves a script from $X_i$ to $Y_{j-1}$, so $|S| - 1 \ge d(i,j-1)$.

— $S$ aligns $x_i$ with $y_j$. Since $x_i \ne y_j$, that alignment must be a substitution, costing 1; removing it leaves a script from $X_{i-1}$ to $Y_{j-1}$, so $|S| - 1 \ge d(i-1,j-1)$.

Either way $|S| \ge 1 + \min$ of the three. ∎

(b) The matching case

Claim: when $x_i = y_j$, some optimal script aligns them at no cost.

Let $S$ be optimal. If it already aligns them, done. Otherwise $S$ either deletes $x_i$ or inserts $y_j$ (or both). Suppose it deletes $x_i$ and inserts a copy of $y_j$ elsewhere: replace both operations by a single free match, saving 2 — contradicting optimality unless no such pair exists. If $S$ deletes $x_i$ and $y_j$ was aligned with some earlier $x_k$, then $x_k = y_j = x_i$, and we may instead align $x_i$ with $y_j$ and delete $x_k$, leaving the length unchanged. Symmetrically for insertions.

So there is an optimal script matching them, and $d(i,j) = d(i-1,j-1)$. ∎

This is the only exchange argument in the proof, and it is what licenses the recurrence to omit the other three options in the matching case. Including them anyway — writing $\min(d(i-1,j-1), 1+d(i-1,j), 1+d(i,j-1))$ — is still correct, by monotonicity, but costs two comparisons per cell for nothing.

(c) The base cases, exactly

$\le i$. Deleting all $i$ characters of $X_i$ gives the empty string, which is $Y_0$. That is $i$ operations.

$\ge i$. Each operation changes the string's length by at most 1 — insertions by $+1$, deletions by $-1$, substitutions by 0. Going from length $i$ to length 0 therefore needs at least $i$ operations. ∎

The length argument is worth remembering on its own: it gives the general bound $d(i,j) \ge |i - j|$, which is a free lower bound and the basis of the banded optimisation in F5(c).

(d) The unit-step property

$d(i,j) \le d(i-1,j) + 1$: take an optimal script for $(i-1,j)$ and prepend a deletion of $x_i$. $d(i-1,j) \le d(i,j) + 1$: take an optimal script for $(i,j)$ and prepend an insertion of $x_i$ into $X_{i-1}$, which reduces the problem to $(i,j)$. So the two differ by at most 1. ∎ (Symmetrically along a row.)

Bits per cell. Combined with $d(i,j) \le \max(i,j) \le 2000$, every entry fits in 11 bits, so an array('H') of 16-bit cells is ample and a full $2001 \times 2001$ table is 8 MB rather than 108 MB. Better still, the unit-step property means a row is determined by its first entry plus $n$ two-bit differences, which is the basis of the bit-parallel Myers algorithm running in $\Theta(mn/w)$.

Note this is exactly the structure Part D lacks — knapsack rows can jump by $\max_i v_i$ — and it is why edit distance admits difference encoding and knapsack does not.

(a) The indel identity

Write $\ell = \operatorname{LCS}(X,Y)$.

$\le$. Let $Z$ be an LCS. Delete from $X$ the $m - \ell$ characters not used by $Z$'s witness, leaving exactly $Z$; then insert the $n - \ell$ characters of $Y$ not used by its witness, in their correct positions, leaving exactly $Y$. Total $m + n - 2\ell$.

$\ge$. Let $S$ be any indel script with $a$ deletions and $b$ insertions. Let $Z$ be the string formed by the characters of $X$ that $S$ never deletes, so $|Z| = m - a$. Since $S$ neither reorders nor alters existing characters, those survivors appear in $Y$ in the same relative order, so $Z$ is a common subsequence and $m - a \le \ell$. Symmetrically the characters of $Y$ that $S$ never inserts are exactly the survivors, so $n - b \le \ell$. Adding, $|S| = a + b \ge m + n - 2\ell$. ∎

The step where "no substitutions" is used is the claim that a surviving character keeps its identity. A substitution changes a character in place, so a survivor could differ between $X$ and $Y$, and $Z$ would not be a common subsequence.

(b) Levenshtein is not a function of the LCS

By (a), the indel distance is completely determined by the triple $(m, n, \ell)$. If Levenshtein were too, then any two pairs agreeing on all three would have equal edit distance. They do not:

pair$m$$n$LCS $\ell$indelLevenshtein
ab, ba22122

Both pairs have two characters each and a longest common subsequence of length 1, so both have indel distance $2 + 2 - 2 = 2$. But ab $\to$ ac needs one substitution, while ab $\to$ ba needs two operations however you do it — one substitution cannot fix both positions. So no function of $(m,n,\ell)$ produces the Levenshtein distance. ∎

What is always true is a pair of bounds:

$$\max(m,n) - \ell \ \le\ L(X,Y) \ \le\ m + n - 2\ell.$$

The upper bound holds because every indel script is an edit script. The lower bound holds because an optimal edit script leaves at most $\ell$ characters untouched, and every other character of the longer string must be produced by some operation. Both are attained — the upper on flaw/lawn, where both distances are 2, and the lower on abc/def, where $\max(m,n) - \ell = 3 - 0 = 3$ is the answer. Verified on 2000 random pairs: the bounds hold in every case, and they are far apart in the middle — kitten/sitting gives $3 \le 3 \le 5$.

The moral: "compute the LCS and adjust" is a real shortcut for indel distance and a wrong one for Levenshtein. Levenshtein needs its own DP.

(d) Metric axioms

Non-negativity: a script length is a count. Identity: $d = 0$ iff no operation is needed iff $X = Y$. Symmetry: reverse a script, swapping insertions with deletions and reversing substitutions; the length is unchanged, so $d(X,Y) = d(Y,X)$. Triangle inequality: concatenating a script from $X$ to $Y$ with one from $Y$ to $W$ gives a script from $X$ to $W$, so $d(X,W) \le d(X,Y)+d(Y,W)$. ∎

The triangle argument uses nothing about the operation set beyond composability, so it holds for indel distance and Damerau–Levenshtein equally. Why this matters: being a metric licenses clustering, nearest-neighbour search, and triangle-inequality pruning of a search index — none of which is available for a similarity score like the raw LCS length, which fails the identity axiom since $\operatorname{LCS}(X,X) = |X| \ne 0$.

(b) The pseudo-polynomial pair

Change and Knapsack. In both, one coordinate of the state is a magnitude from the input — the amount $X$, the capacity $W$ — rather than a count of input items. Since a number of magnitude $W$ is written in $\Theta(\log W)$ bits, a table of size $W$ is exponential in the length of its own description.

The word means: polynomial in the numeric values appearing in the input, exponential in their lengths. The practical signature is sensitivity to magnitude — adding ten characters to the capacity multiplies the work by $10^{10}$ — and it is why both of those problems cap their magnitude coordinate in the constraints while the other four cap only lengths.

The other four are genuinely polynomial: $m$, $n$, $V$, $E$ are all counts of things actually present in the input, so a table of size $mn$ is quadratic in the input size.

(c) Linear states, quadratic time

Ascending. The state is a single index, so there are only $n$ states — yet each has up to $n$ transitions, because $f(i)$ takes a maximum over all earlier indices with a smaller value.

No contradiction: time is states times transitions, not states alone. Counting only states gives $\Theta(n)$ and is simply the wrong quantity. The lesson runs the other way too — Common and Edit have $\Theta(mn)$ states and only 1 to 3 transitions each, so their time matches their state count, and Longest Path has $V$ states whose transitions sum to $E$ rather than $V \cdot E$.

And the $\Theta(n^{2})$ is not intrinsic: E5's patience method computes the same answer in $O(n\log n)$ by never materialising the transitions at all. State count bounds memory; it does not bound time in either direction.

(d) The discriminating question

Is every coordinate of the state a count of something present in the input, or is some coordinate a magnitude the input merely names?

Minimising a count is maximising a sum of $-1$s. The extra condition is about how full the sack must be.

(a) The reduction

Each coin $c$ becomes an item of weight $c$ and value $-1$, usable any number of times; the capacity is the amount $X$. Maximising total value then minimises the coin count, since every coin contributes exactly $-1$.

The extra condition is exact fill. Knapsack permits an under-full sack; Change demands that the coins sum to $X$ precisely. That is encoded in the base case: every capacity other than 0 starts unreachable, rather than starting at 0.

(b) Implementation 
NEG = float('-inf')

def change_via_knapsack(amount, coins):
    """Minimum coins summing to exactly `amount`, or None."""
    dpt = [NEG] * (amount + 1)
    dpt[0] = 0                                # only the empty sum is free

    for x in range(1, amount + 1):            # ascending sweep = unbounded
        for c in coins:
            if c <= x and dpt[x-c] != NEG:
                cand = dpt[x-c] - 1
                if cand > dpt[x]:
                    dpt[x] = cand

    return None if dpt[amount] == NEG else -dpt[amount]

(a) The reduction

Let $S = \sum_i a_i$. If $S$ is odd, print NO immediately — two equal integer groups cannot sum to an odd total. Otherwise the question is whether some subset sums to exactly $S/2$, since the complement then also sums to $S/2$.

That is 0-1 Knapsack with $w_i = v_i = a_i$ and capacity $S/2$: the answer is YES exactly when the optimum equals $S/2$, because the best achievable value never exceeds the capacity and equals it precisely when some subset fills it. Equivalently — and more cheaply — run the same DP over booleans: is capacity $w$ exactly achievable?

(b) Implementation 
import sys

def main():
    data = sys.stdin.buffer.read().split()

Descending, for exactly the reason of D6(a): the update at $w$ reads reach[w-x], which must still reflect the state before this number was considered. An ascending sweep would read a cell already updated with $x$, allowing $x$ to be used repeatedly — which solves the unbounded variant and answers YES on sample 2, since $4 = 2+2$.

That is the whole trap in this problem, and it is a one-word error that returns a plausible answer.

(c) Cost at the limits

$S \le 200 \times 1000 = 2 \times 10^{5}$, so the target is at most $10^{5}$. Time $\Theta(n \cdot S/2) = 200 \times 10^{5} = 2 \times 10^{7}$ operations. Memory $\Theta(S/2)$, one row of at most $10^{5}$ cells.

Time is the real constraint here, unlike Parts C, D and F where memory bound first. $2 \times 10^{7}$ inner iterations in pure Python is several seconds — borderline — while $10^{5}$ cells is trivial whatever the representation. The reason is that the one-row optimisation is not optional here; it comes free with the boolean formulation, so the memory problem never arises.

(d) The memory improvement

Already partly taken: a bytearray is 1 byte per cell against 28 for a list of Python integers — a factor of 28 — because the values are booleans and need no object per cell.

Further, use a single big integer as a bitmask:

    reach = 1                                  # bit w set  <=>  sum w achievable
    for x in a:
        reach |= reach << x
    print("YES" if (reach >> target) & 1 else "NO")

One bit per cell — another factor of 8, so $10^{5}$ bits is 12.5 KB — and, more importantly, the shift-and-or does 64 cells per machine word, turning the $2 \times 10^{7}$ operations into roughly $3 \times 10^{5}$. That is the bit-parallel trick from Part A's feasibility discussion, and it applies here for the same reason: the table holds bits rather than numbers. It works only because the question is "is it achievable?" and not "what is the best value?" — the moment the cells hold numbers, the trick is unavailable.

Note the mask version needs no explicit sweep direction. reach | (reach << x) reads the whole old mask and writes a new one, so there is no in-place overwriting to get wrong — the correctness question that D6 is entirely about simply does not arise. That is worth noticing as a general point: expressing a row update as a pure function of the old row eliminates a whole class of bug.

(b) The condition, and $X+1$

For a minimisation, a sentinel $A$ standing for $\infty$ must satisfy: (i) $A$ strictly exceeds every finite optimal value in the table, so it never wins a minimum it should lose; and (ii) $A$ plus any transition cost still exceeds every finite value, so unreachability propagates.

$A = X+1$ satisfies (i): any finite $f(x)$ uses coins of value $\ge 1$ summing to $x \le X$, so $f(x) \le x \le X \lt A$. And (ii): the only transition cost is $+1$, so a sentinel-derived candidate is $A+1 \gt A$, still above every finite value. ∎

(c) The asymmetry

It is not really about $+\infty$ versus $-\infty$; it is about which direction the transition moves the value. In a minimisation with non-negative costs, an unreachable state's value only grows as costs are added, so it stays above any threshold you test against — no guard needed, only a $\ge$ in the final test.

In a maximisation where transitions subtract — as in G3, where each coin contributes $-1$ — an unreachable state's sentinel drifts towards the finite values with every relaxation. After enough steps a $-\infty$ implemented as a large negative integer can cross into the range of real answers and start winning maxima it should lose. Hence the explicit if dpt[x-c] != NEG guard in G3(b).

With a true floating-point $-\infty$ the arithmetic saturates and the guard is unnecessary — but relying on that is relying on a property of the representation rather than of the algorithm, and it breaks the moment someone swaps in a fixed-width integer for speed. Guard the sentinel explicitly and the code survives the representation change.

(d) The rule

The base case must state what is achievable with nothing, not what is cheap with nothing — so ask "is this state genuinely solvable by doing nothing?" and use a sentinel wherever the answer is no.

(b) The walk is bounded by the longest chain

A traceback walk starts at the target state and moves to one of its predecessors at each step, halting at a base state. Every step therefore traverses one edge of the dependency DAG in reverse, and the sequence of visited states is a directed path in that DAG. So the number of steps is at most the length of the longest directed path from the target — the longest chain. ∎

Common: every edge decreases $i+j$ by 1 or 2, and $i+j \le m+n$, so the longest chain is $m+n$ and the walk is $O(m+n)$. The bound is attained: on $X = \texttt{A}^{m}$, $Y = \texttt{B}^{n}$ nothing matches, so every step is an up or a left, decreasing $i+j$ by exactly 1, and the walk takes the full $m+n$ steps while collecting nothing. Pleasingly, the worst case for the walk is the input with the smallest answer.

Knapsack: every edge decreases $i$ by exactly 1, so the longest chain is $N$ and the walk is $O(N)$ — independent of $W$, which is why D4(d)'s traceback is so cheap.

(c) Parents are never necessary for Common

The fill writes $\texttt{dpt}[i][j]$ in one of three branches, tested in order: $x_i = y_j$; else $\texttt{dpt}[i-1][j] \gt \texttt{dpt}[i][j-1]$; else. A traceback can re-evaluate exactly those conditions, on exactly those values, and obtain exactly the branch the fill took.

The step making this legitimate is that the fill never overwrites a cell, so $\texttt{dpt}[i-1][j]$ and $\texttt{dpt}[i][j-1]$ still hold the values the branch test saw. Hence the re-derived decision is identical, not merely equivalent. ∎ Verified: on 2000 random pairs, the parent-pointer version and the parent-free version return the same string character for character.

Memory saved. A parent table holds a tuple per cell — 56 bytes for the tuple plus 8 for the slot — against 28 bytes for an integer, so it is roughly 2–3× the value table rather than equal to it. At $m = n = 2000$ the value table is about 107 MB and the parent table about 256 MB; dropping it takes the program from "will not run" to "will run", with no change to the answer.

The same argument applies to Knapsack (D4(d)), Ascending (E3(c)) and Edit. Change is the one exception worth naming: re-deriving there costs a scan of all $N$ coins, so a one-integer choice array genuinely pays when $N$ is large. Store the decision, never the pointer, and only when re-deriving it is expensive.

(d) The precondition

Traceback is possible exactly when the states an optimal solution passed through are still available, and their values still determine which choice was optimal.

Two ways to fail, one per clause. The states are gone: memory optimisation discards every layer but the last, and the walk visits one state per layer — which is why C6 and D6 lose it, and why the repair is divide and conquer rather than storing more. The determination is gone: a transition that cannot be reproduced — one using a random draw, a floating-point comparison that may not repeat bit-for-bit, or a caller-supplied function you may not invoke twice — leaves the value table unable to say which branch won, and then the pointer is the only record.

How to use this

Anything you could not produce from memory is the thing to revise, and the fastest way to revise it is to redo the one question on this sheet it came from. The numbering above follows the sheet's parts in order.

Built from CITS3001 Lectures 9 and 10, Dynamic Programming and DP Techniques (Department of Computer Science and Software Engineering, UWA, Semester 2 2026). Each part is one problem, stated in judge format: coin change and DAG longest paths come from Lecture 9; longest common subsequence, 0-1 knapsack and edit distance from Lecture 10; longest increasing subsequence is the standard companion problem whose state is the instructive one to get wrong. The two corrections flagged in the header are marked again at B5 and C5.

Every numeric answer, table, sample and test vector on this sheet was computed and cross-checked before being written down — the sample inputs and outputs against reference implementations, the counterexamples by exhaustive search, and the one-row and reduction variants against the full-table versions on hundreds of random inputs. The sample blocks are in the same whitespace-delimited format a judge would use; the extra-test blocks are meant to be pasted and run against your own solutions.

Printing uses the same palette as the screen, with all answers revealed.
