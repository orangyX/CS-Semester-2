Logic refresher

Propositions · predicates · deductive proof · built for CITS3001 proof work now, CITS3005 later

How to use this. Every question has its answer attached to it, not at the back. Attempt it on paper first, then hit Check — the point is a tight write → verify loop, the same feedback rhythm that works for you on lab code.

Six sets, 15–30 min each. One set per morning block. Don't do the whole thing in a sitting — that's the pattern that burns.

Amber boxes are traps: places where the wrong answer is the tempting one. Read those even when you got the question right.

01

Propositions and translation

~15 min

1.1 Which of these are propositions? For any that aren't, say why not.

  • (a) x + 3 = 7
  • (b) Perth is the capital of Western Australia.
  • (c) Sort the array.
  • (d) This sentence is false.
  • (e) Every even integer greater than 2 is a sum of two primes.
▶Check
  • (a) No. Open sentence — truth depends on x. It's a predicate, and becomes a proposition once x is assigned or quantified.
  • (b) Yes, and true.
  • (c) No. Imperative — commands have no truth value.
  • (d) No. Paradoxical; no consistent truth value can be assigned.
  • (e) Yes. This is Goldbach's conjecture — nobody knows whether it's true, but it has a truth value. Unknown ≠ undefined.

1.2 Let p = "the algorithm terminates", q = "the input is sorted", r = "the array is non-empty". Translate:

  • (a) The algorithm terminates only if the input is sorted.
  • (b) The algorithm terminates if the input is sorted.
  • (c) The algorithm terminates unless the array is empty.
  • (d) A non-empty array is necessary for termination.
  • (e) A sorted input is sufficient for termination.
  • (f) Neither is the input sorted, nor is the array empty.
  • (g) The algorithm terminates if and only if the array is non-empty.
▶Check
(a) p → q (b) q → p (c) r → p ["A unless B" ≡ ¬B → A; here B = ¬r] (d) p → r (e) q → p (f) ¬q ∧ r (g) p ↔ r

Sanity check on (c): ¬B → A ≡ B ∨ A, so r → p ≡ ¬r ∨ p — "either the array is empty, or it terminates". Matches the English.

Trap — "only if" vs "if". Only if introduces the consequent: "p only if q" is p → q. Plain if introduces the antecedent: "p if q" is q → p. Same two letters, opposite arrows. Same rule powers (d) and (e): a necessary condition sits on the right of the arrow, a sufficient condition on the left.
02

Truth tables and equivalence

~20 min

2.1 Build the full truth table for ((p → q) ∧ (q → r)) → (p → r) and classify it as a tautology, contradiction, or contingency.

▶Check

Tautology — all 8 rows come out true. This is hypothetical syllogism written as a single formula.

Shortcut worth internalising: the whole thing is false only if the antecedent is true and p → r is false. That needs p = T, r = F. Then p → q forces q = T, and q → r forces r = T. Contradiction — so no falsifying row exists.

2.2 Verify by truth table: ¬(p ∧ q) ≡ ¬p ∨ ¬q, and p → q ≡ ¬p ∨ q.

▶Check
p q │ ¬(p∧q) ¬p∨¬q │ p→q ¬p∨q ─────┼─────────────────┼───────────── T T │ F F │ T T T F │ T T │ F F F T │ T T │ T T F F │ T T │ T T

Both columns match. The second one — implication is just a disjunction in disguise — is the single most useful rewrite you have. It's how you get rid of arrows before applying De Morgan, and it's the first step of converting to CNF.

2.3 True or false: (p ∨ q) → r ≡ (p → r) ∧ (q → r)

▶Check

True. The left side fails exactly when p ∨ q holds and r doesn't. The right side fails exactly when r is false and at least one of p, q is true. Same condition.

Read it as: to prove r follows from "p or q", handle each case separately. That is proof by cases.

2.4 True or false: (p ∧ q) → r ≡ (p → r) ∧ (q → r)

▶Check

False. Counterexample: p = T, q = F, r = F.

LHS: (T ∧ F) → F = F → F = T RHS: (T → F) ∧ (F → F) = F ∧ T = F

The correct distribution is (p ∧ q) → r ≡ p → (q → r) — exporting a conjunctive hypothesis into nested arrows.

Trap — 2.3 and 2.4 look symmetric and aren't. ∨ in the antecedent distributes over the arrow; ∧ in the antecedent does not. If you find yourself reasoning "well the other one worked", stop and test a row instead. One counterexample row settles it faster than any intuition.

2.5 Classify (p → q) ∨ (q → p).

▶Check

Tautology — which feels wrong the first time you see it.

For it to be false, both disjuncts must be false. p → q false needs p = T, q = F. q → p false needs q = T, p = F. Can't have both, so it's never false.

This is the material conditional showing its teeth: it doesn't track relevance or causation, only truth values.

2.6 Express exclusive-or p ⊕ q using only ∧, ∨, ¬. Give two different forms.

▶Check
(p ∨ q) ∧ ¬(p ∧ q) "at least one, but not both" (p ∧ ¬q) ∨ (¬p ∧ q) "exactly this case, or exactly that one"

The first mirrors the English definition; the second is the disjunctive normal form you'd read straight off the true rows of the truth table. Being able to produce DNF from a truth table by inspection is a genuinely reusable trick.

03

Converse, inverse, contrapositive

~15 min

3.1 Take the true statement S: "If a graph on n vertices is connected, then it has at least n − 1 edges." Write the converse, the inverse, and the contrapositive, and say whether each is true.

▶Check
  • Converse — if it has at least n − 1 edges, it's connected. False. Take n = 4: a triangle on three vertices (3 edges = n − 1) plus one isolated vertex. Edge count satisfied, still disconnected.
  • Inverse — if it's not connected, it has fewer than n − 1 edges. False, same counterexample.
  • Contrapositive — if it has fewer than n − 1 edges, it's not connected. True, necessarily, because it's logically equivalent to S.

The pattern: S ≡ contrapositive, and converse ≡ inverse. Two equivalence classes, and one counterexample kills a whole class at once.

3.2 Is "every element of the empty set is prime" true or false?

▶Check

True, vacuously. Unpacked, it's ∀x (x ∈ ∅ → prime(x)), and the antecedent is false for every x, so every instance of the conditional is true.

This matters in induction base cases and in loop invariants for an empty input — the invariant usually holds vacuously before the first iteration, and that's a legitimate base case, not a cheat.

3.3 True or false: "If 2 + 2 = 5, then I am the Queen of England."

▶Check

True. False antecedent, so the material conditional is satisfied regardless of the consequent.

The lesson isn't the party trick — it's that → carries no notion of relevance, causation, or temporal order. Everyday "if...then" does. When a translation feels wrong, it's usually this mismatch.

3.4 You know P → Q is true and Q is true. What can you conclude about P?

▶Check

Nothing at all. Both P = T and P = F are consistent with those two facts.

Concluding P here is affirming the consequent — the single most common invalid step in student proofs, and it's coming up again in Set 5.

04

Predicates and quantifiers

~25 min
Domain for 4.1–4.2: all algorithms. S(x) = "x is a sorting algorithm", P(x) = "x runs in polynomial time", F(x,y) = "x is faster than y".

4.1 Translate into predicate logic:

  • (a) Some sorting algorithm runs in polynomial time.
  • (b) Every sorting algorithm runs in polynomial time.
  • (c) No sorting algorithm runs in polynomial time.
  • (d) There is an algorithm faster than every other algorithm.
  • (e) Every algorithm has something faster than it.
▶Check
(a) ∃x (S(x) ∧ P(x)) (b) ∀x (S(x) → P(x)) (c) ∀x (S(x) → ¬P(x)) ≡ ¬∃x (S(x) ∧ P(x)) (d) ∃x ∀y (x ≠ y → F(x,y)) (e) ∀x ∃y (x ≠ y ∧ F(y,x))

The x ≠ y guard in (e) is strictly speaking redundant if you assume "faster than" is irreflexive — but state it anyway. A reasoner doesn't share your background assumptions about the relation unless you axiomatise them.

(d) and (e) are not variations on one claim — they are close to opposites. (d) says a fastest algorithm exists; (e) says every algorithm is beaten by something, i.e. there is no fastest. Under a strict order they can't both hold. See 4.3.

Trap — the connective that pairs with each quantifier. ∃ takes ∧; ∀ takes →. Writing (a) as ∃x (S(x) → P(x)) is satisfied by any non-sorting algorithm at all, since the antecedent is false — so it claims almost nothing. Writing (b) as ∀x (S(x) ∧ P(x)) claims every object in the domain is a sorting algorithm. Both are much more common than you'd expect under exam pressure.

4.2 Negate each of these and push the ¬ all the way inward:

(a) ¬ ∀x (S(x) → P(x)) (b) ¬ ∃x ∀y F(x,y) (c) ¬ [ ∀ε > 0 ∃N ∀n > N ( |aₙ − L| < ε ) ]
▶Check
(a) ∃x (S(x) ∧ ¬P(x)) (b) ∀x ∃y ¬F(x,y) (c) ∃ε > 0 ∀N ∃n > N ( |aₙ − L| ≥ ε )

Mechanical rule: each quantifier flips (∀ ↔ ∃) as the negation moves past it, and the innermost body gets negated. For (a) you also need ¬(A → B) ≡ A ∧ ¬B.

(c) is the definition of "the sequence does not converge to L" — and this exact shape reappears in STAT2062 and in any convergence or bound argument. Being able to negate a three-quantifier statement without thinking is worth real marks.

4.3 Domain is ℝ. Which of these is true?

(a) ∀x ∃y (x + y = 0) (b) ∃y ∀x (x + y = 0)
▶Check

(a) is true — for each x, pick y = −x. The choice of y is allowed to depend on x.

(b) is false — it demands a single y that works for every x simultaneously. No such real number.

Trap — quantifier order is not decoration. ∃∀ is strictly stronger than ∀∃: it asserts one witness covers everything. Whenever you see nested quantifiers, ask "is the inner witness allowed to depend on the outer variable?" That's the whole distinction, and it's exactly the difference between pointwise and uniform convergence, and between "each input has a fast algorithm" and "one algorithm is fast on all inputs".

4.4 In ∀x (P(x) ∧ Q(y)), which variables are bound and which are free? Is this a proposition?

▶Check

x is bound by the quantifier; y is free.

Not a proposition — it has no truth value until y is assigned or quantified. A formula with a free variable is a predicate, exactly like x + 3 = 7 back in 1.1.

05

Inference rules and fallacies

~20 min

5.1 Name each form, and mark it valid or invalid.

(a) p → q, p ⊢ q (b) p → q, ¬q ⊢ ¬p (c) p → q, q ⊢ p (d) p → q, ¬p ⊢ ¬q (e) p ∨ q, ¬p ⊢ q (f) p → q, q → r ⊢ p → r (g) p ∨ q, ¬p ∨ r ⊢ q ∨ r
▶Check
  • (a) Modus ponens — valid
  • (b) Modus tollens — valid
  • (c) Affirming the consequent — invalid
  • (d) Denying the antecedent — invalid
  • (e) Disjunctive syllogism — valid
  • (f) Hypothetical syllogism — valid
  • (g) Resolution — valid

(g) is the one everything in automated reasoning is built on — it's the sole inference rule a resolution prover needs, and it's why CNF conversion matters. Worth knowing cold before KR.

5.2 Derive ¬p. Cite a rule at every line.

1. p → q premise 2. q → r premise 3. ¬r premise ⊢ ¬p
▶Check
4. p → r 1, 2 hypothetical syllogism 5. ¬p 4, 3 modus tollens

Alternative route, same length: ¬q from 2 and 3 by modus tollens, then ¬p from 1 and that, again by modus tollens. Both are fine — there's rarely a unique proof.

5.3 Derive r from p ∨ q, p → r, q → r.

▶Check

This is proof by cases (constructive dilemma). Case p: modus ponens on p → r gives r. Case q: modus ponens on q → r gives r. The disjunction guarantees one case holds, and both deliver r.

Compare 2.3 — this is that equivalence used as a proof strategy rather than stated as a formula.

5.4 Is this valid? "If the program has a memory leak it slows down. The program slowed down. Therefore it has a memory leak."

▶Check

Invalid — affirming the consequent. Slowdown has plenty of other causes: swapping, lock contention, a cold cache.

This is what debugging by assumption looks like formally, and it's why the symptom-to-cause direction always needs evidence rather than inference.

5.5 Give an argument that is valid but not sound.

▶Check
All prime numbers are even. 7 is prime. ∴ 7 is even.

Valid: the conclusion follows necessarily from the premises. Unsound: the first premise is false.

Validity is about form only. Soundness = validity + all premises actually true. A marker checking your proof is checking validity; whether your assumptions were right is a separate question.

06

Proof strategies

~30 min

6.1 Direct. Prove: if n is odd then n² is odd.

▶Check

Let n = 2k + 1 for some integer k. Then

n² = 4k² + 4k + 1 = 2(2k² + 2k) + 1

which is of the form 2m + 1, hence odd. ∎

The move that does all the work is turning the word "odd" into the algebraic form 2k + 1 immediately. Unfold definitions first, then compute.

6.2 Contraposition. Prove: if n² is even then n is even.

▶Check

The contrapositive is: if n is odd then n² is odd — which is exactly 6.1, already proved. ∎

Direct attack here is painful: "n² is even" gives you n² = 2k, and extracting information about n from that requires unique factorisation. When the hypothesis is a weak or awkward starting point, try flipping to the contrapositive — you often get a much more usable hypothesis.

6.3 Contradiction. Prove √2 is irrational.

▶Check

Suppose not: √2 = a/b with a, b integers sharing no common factor.

2b² = a² → a² is even → a is even [by 6.2] a = 2c ⟹ 2b² = 4c² ⟹ b² = 2c² → b is even [by 6.2 again]

So a and b share a factor of 2, contradicting the assumption that the fraction was in lowest terms. Hence no such a, b exist. ∎

Note how 6.2 gets used twice as a lemma. Building small results and reusing them is most of what proof-writing actually is.

6.4 Cases. Prove n² + n is even for every integer n.

▶Check

Case n even: n = 2k, so n² + n = 4k² + 2k = 2(2k² + k). Even.

Case n odd: n = 2k + 1, so n² + n = n(n + 1) = (2k+1)(2k+2) = 2(2k+1)(k+1). Even.

Cases are exhaustive, so the claim holds for all n. ∎

Slicker: n² + n = n(n + 1) is a product of consecutive integers, one of which must be even. Worth noticing that factoring first can collapse a case analysis entirely.

6.5 Induction. Prove 1 + 3 + 5 + ⋯ + (2n − 1) = n² for all n ≥ 1.

▶Check

Base n = 1: left side is 1, right side is 1² = 1. ✓

Step: assume the sum to (2k − 1) equals k². Then

k² + (2k + 1) = (k + 1)²

which is the claim at k + 1. By induction it holds for all n ≥ 1. ∎

Write the inductive hypothesis out explicitly every time, and say where you use it. Markers look for that sentence specifically.

6.6 Induction, algorithmic flavour. Prove a binary tree of height h has at most 2^(h+1) − 1 nodes.

▶Check

Base h = 0: a single node, and 2¹ − 1 = 1. ✓

Step: a tree of height h + 1 is a root plus two subtrees each of height at most h. By the hypothesis each has at most 2^(h+1) − 1 nodes, so the total is at most

1 + 2(2^(h+1) − 1) = 2^(h+2) − 1

which is the bound at h + 1. ∎

This is the shape most CITS3001 correctness and complexity proofs take: induct on a structural parameter (height, size, iteration count) rather than on a plain integer.

6.7 Strong induction. Prove every integer n > 1 has a prime factorisation. Why won't ordinary induction do?

▶Check

Assume every integer from 2 up to n − 1 factors into primes. If n is prime, it's its own factorisation. Otherwise n = ab with 1 < a, b < n; both are covered by the hypothesis, so concatenating their factorisations factors n. ∎

Ordinary induction fails because it only hands you the case n − 1, and the factors a and b are nowhere near n − 1. You need all smaller cases available.

The tell: reach for strong induction whenever the recursive step jumps by an unpredictable amount — divide-and-conquer recurrences, most tree and interval arguments.

6.8 Strategy selection. Which technique would you reach for first?

  • (a) There are infinitely many primes.
  • (b) 2ⁿ ≥ n + 1 for all n ≥ 1.
  • (c) If x is irrational then 1/x is irrational.
  • (d) n³ − n is divisible by 6 for every integer n.
▶Check
  • (a) Contradiction. Assume finitely many, form p₁p₂⋯pₖ + 1, derive a contradiction.
  • (b) Induction. A claim indexed by n with an obvious base case.
  • (c) Contraposition. "If 1/x is rational then x is rational" gives you an actual fraction to manipulate; the original hypothesis gives you only a negative fact.
  • (d) Cases (or factor first: n³ − n = (n−1)n(n+1), three consecutive integers, so divisible by both 2 and 3).

Rough heuristic: indexed by n → induction. Hypothesis is a negative or an irrationality → contraposition or contradiction. Conclusion is "no such thing exists" → contradiction. Domain splits naturally → cases.

6.9 Is checking that a claim holds for n = 0, 1, 2, …, 39 a proof?

▶Check

No. The standard cautionary example: n² + n + 41 is prime for every n from 0 to 39, and then at n = 40 it gives 1681 = 41².

Examples build confidence and suggest what to try. Only a general argument closes it. The reverse does hold though — a single counterexample is a complete disproof, which is why hunting for one is always worth ten minutes before you commit to proving something.
